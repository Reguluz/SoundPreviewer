# 合成器预制音色库：项目计划

整理日期：2026-10-05。技术调研日期：2026-10-03。

本文是新项目的独立启动文档，汇总已确认的需求、建议架构、开发阶段和验收标准。现阶段完成了公开文档与源码调研，尚未使用实际插件和预制开展兼容性测试；下文技术选型为候选方案，具体接口与性能必须通过原型验证。

## 1. 目标与已确认约束

用户拥有散落在多个目录中的大量合成器预制，缺少统一预览音，难以快速遍历与挑选。开发一个独立于 DAW 的桌面软件，由用户指定已安装音源和预制目录，自动逐个加载音色、播放指定 MIDI 音符、保存预览音及映射关系，随后提供检索、试听和个人偏好排序。

| 项目 | 已确认要求 |
| --- | --- |
| 优先音源 | Serum、Vital、Sylenth1 |
| 基准设备 | 16GB 内存、2GB 显存；CPU 型号未指定 |
| 操作系统 | Windows 优先，后续考虑 macOS |
| 运行方式 | 必须本地运行，预制、音乐、音频特征与个人反馈均保留在本机 |
| 基础试听 | 低、中、高音区各选用户指定音符，分别播放一次 |
| 个性化 | 分析音色，并结合用户历史音乐喜好进行推荐排序 |
| 模型倾向 | 优先开源、可本地运行的小模型；不要求必须使用生成式大模型 |

软件不依赖用户打开 DAW，但内部仍需包含插件宿主或调用音源原生渲染能力。用户自行安装音源，并持有可支持相应离线工作方式的有效授权。

## 2. 产品范围与优先级

首先交付可靠的预览音生成与统一浏览，再加入音频相似搜索，最后加入偏好学习。推荐系统的效果不能成为基础音色库可用性的前提。

第一版应覆盖：

- 指定插件和一个或多个预制目录，递归扫描支持的文件与银行。
- 配置三段单音试听，批量生成本地预览。
- 音色名称、所属音源、包与目录、原文件位置的统一索引。
- 点击即可试听已生成音频，无需重新加载插件。
- 搜索、筛选、收藏、喜欢／不喜欢反馈。
- 任务进度、暂停与继续、失败记录和有限重试。
- 新增与修改预制的增量处理，已有有效预览无需重复生成。

后续扩展：自定义 MIDI 试听片段、相似音色搜索、参考音乐片段匹配、个人偏好排序、可选自然语言搜索和 macOS 支持。

第一版暂不承诺任意合成器的零配置支持，也不承诺从完整歌曲中准确识别原始合成器及具体预制。

## 3. 总体架构

生成流程：

```text
插件与预制目录
    → 扫描、识别格式、生成任务
    → 音源专用适配器
    → 独立插件工作进程或原生渲染进程
    → MIDI 演奏与音频采集
    → 结果校验
    → 音频文件、映射索引与任务状态
    → 本地音频分析与推荐排序
    → 统一音色浏览器
```

浏览器读取预览文件与索引，音频分析读取生成结果，两者都不应阻塞插件的音频处理线程。

| 模块 | 职责 |
| --- | --- |
| 桌面界面 | 配置音源与目录、任务控制、浏览试听、反馈 |
| 扫描与索引 | 文件发现、去重、银行展开、资源信息、变更检测 |
| 任务调度 | 队列、进度、断点继续、超时与有限重试 |
| 音源适配器 | 对应插件版本的预制加载、音色枚举、加载结果确认 |
| 插件工作进程 | 实例化插件、发送 MIDI、设置播放信息、采集音频 |
| 结果校验 | 检测静音、异常数值、削波风险、可疑重复和加载错误 |
| 音频分析 | 常规音频特征、模型向量、相似搜索 |
| 推荐模块 | 参考片段匹配、用途匹配、个人反馈学习 |
| 本地存储 | SQLite 索引、预览音、版本化的分析结果与反馈 |

原型候选：Python、DawDreamer、PySide6、SQLite。产品化时评估 C++／JUCE 宿主，并让本地分析作为独立进程运行。先验证真实插件兼容性，再决定是否需要更换或扩展宿主，不预设必须重写。

## 4. 三个音源的适配方案

插件格式与预制格式是两件事。能加载 VST3 插件，不代表能够直接读取该合成器的专有预制文件。每个音源都需要验证自己的加载路径。

### 4.1 Vital

优先验证已安装版本的原生无界面渲染功能。公开源码包含 `--headless`、`--render`，以及 MIDI 音高、长度、BPM 设置。若满足试听需求，可绕过界面操作；需要更复杂 MIDI 演奏时，再验证插件宿主或专用渲染适配器。

处理对象包括单预制 `.vital` 和音色包 `.vitalbank`。读取包时保留内部路径及资源关系，不假设所有内容都可以当作独立预制直接加载。

验证重点：源码与官方二进制差异、预制版本兼容性、外部资源、Windows 路径与输出行为，以及原生渲染对力度和尾音控制的覆盖程度。

### 4.2 Serum

必须区分 Serum 1 与 Serum 2。Serum 1 常见单预制格式为 `.fxp`；Serum 2 使用 `.SerumPreset`，旧格式如何加载应按实际版本验证。

已有 `vst-render` 项目使用 DawDreamer 批量渲染这两类预制，可作为实验起点。先验证其支持的插件格式、加载机制和项目依赖，再决定复用范围。不要把该项目声明的支持直接视为本产品已经完成的兼容性。

保留通过插件自身界面加载文件的备用方案。加载后可尝试保存宿主状态，作为后续重新渲染的缓存，但状态缓存仍可能依赖插件版本和外部资源。

验证重点：Serum 具体版本、VST2／VST3 差异、波表与采样依赖、异步加载完成、首次渲染行为、连续切换是否遗漏或沿用旧音色。

### 4.3 Sylenth1

单预制 `.fxp` 与音色银行 `.fxb` 分开处理。官方说明一个银行最多包含 512 个音色，分为四个子银行。

单预制逐个加载；银行先加载一次，再枚举或逐个选择内部音色。银行音色的身份至少包含银行文件哈希与槽位索引，名称不能作为唯一标识。

优先验证宿主对银行加载和程序切换的接口。DawDreamer 现有接口是否完整覆盖此需求尚未确认，必要时扩展宿主或使用固定界面流程。

验证重点：银行槽位、子银行边界、空白／Init 音色识别、相同名称的不同音色、实际插件版本与格式。

## 5. 界面自动化与视觉识别

按下列顺序选择加载方式：

1. 原生渲染、宿主接口或插件状态接口。
2. 音源专用适配器。
3. 固定的菜单、快捷键与文件对话框操作。
4. 本地 OCR 与图像匹配，用于定位控件并确认结果。

界面自动化采用有明确状态与超时的流程，例如“打开加载菜单 → 选择文件 → 等待进度结束 → 确认预制名称”。系统文件对话框优先使用可用的系统控件接口；插件自绘界面可能只能使用图像与 OCR。

视觉识别首先承担验证职责，避免仅因点击完成就宣称加载成功。结合预制名称、加载提示、插件状态和实际音频检查；无法确认时记录不确定结果。

固定窗口尺寸、缩放与皮肤配置，并为已测试插件版本保存对应适配配置。窗口坐标应以目标窗口为基准，不使用未经定位的桌面绝对坐标。

本地 OCR 候选为 PaddleOCR。Qwen3-VL-2B 等视觉语言模型仅作为后续处理陌生弹窗的可选能力，在 2GB 显存基准下不作为必需依赖。即使加入模型，也需限制操作范围并验证每一步。

## 6. 演奏、采集与预览规范

基础模板：三个用户可修改的 MIDI 音高，建议初始值为 36、60、84。以 MIDI 数字作为规范值，避免不同软件的八度命名差异。

| 配置 | 要求 |
| --- | --- |
| 音高 | 低、中、高音区分别设置 |
| 力度 | 明确保存到试听模板；第一版可用固定力度 |
| 按键时长 | 可修改，允许慢起音音色使用更长设置 |
| 尾音 | 记录 Note Off 后的释放，设置最大长度 |
| BPM 与播放信息 | 提供插件所需的速度、传输状态和位置 |
| 采样率与格式 | 明确配置并存入索引，不能隐式随设备变化 |
| 效果 | 默认保留预制自身效果，另行修改须形成不同试听模板 |
| 试听音量 | 保留原始输出，试听可应用单独的统一增益 |

逐音色流程：

1. 加载目标预制，等待并验证加载结果。
2. 清理残留 MIDI，处理上一音色的尾音与活动声部。
3. 按模板依次演奏三个音符，保留各自起音、持续和释放阶段。
4. 直接采集插件输出的数字音频。
5. 检查异常，写入预览文件并提交索引。
6. 继续下一任务；错误时有限重试，必要时重启工作进程。

支持时使用离线渲染；插件不兼容离线处理时，允许实时处理并直接保存插件输出。无需以系统回录作为默认采集方式。

静音、相似音频和较长加载时间属于检查线索，不一律判失败。宏、调制轮、力度、音域、播放状态都可能影响是否发声。随机振荡器与调制也可能导致同一预制每次输出不同，不要求音频逐样本相同。

后续增加用途模板：Bass 短句、Lead 旋律与连奏、Pad 长音与和弦、Arp 同步节奏，以及用户导入的 MIDI。用户提出的三单音模板始终保留。

## 7. 索引、缓存与任务可靠性

每个音色至少记录：

| 类型 | 字段 |
| --- | --- |
| 音色来源 | 原路径、文件哈希、所属包、内部路径、银行槽位 |
| 插件 | 产品标识、插件格式、版本、架构、适配器版本 |
| 依赖 | 已发现的波表／采样位置、缺失资源与加载提示 |
| 演奏 | 音高、力度、按键时长、尾音、BPM、MIDI 模板哈希 |
| 输出 | 音频位置、采样率、声道、长度、输出质量状态 |
| 分析 | 特征版本、模型与权重版本、向量、标签 |
| 任务 | 未处理／处理中／完成／失败／待确认、重试数、原因 |
| 反馈 | 收藏、喜欢／不喜欢、两两比较、用途、时间 |

缓存键结合音色内容、插件版本、试听模板、适配器与渲染设置。更新分析模型只重算分析结果；预制或演奏设置变化时才重新渲染。修改外部依赖也应触发相应检查。

音频先写临时文件，完成后提交，避免中断留下的半成品被当作有效缓存。应用重启时恢复未完成任务，并校验数据库与音频文件的一致性。

插件扫描、实例化与渲染在独立工作进程中执行，主界面负责调度。第一版默认一个音源工作进程，记录超时、崩溃和缺失依赖；失败任务不无限重试。

## 8. 本地音频分析

采用“常规音频特征＋预训练音频向量”，优先验证小模型，不从头训练大型声音模型。

| 层级 | 候选方案 | 用途与限制 |
| --- | --- | --- |
| 常规特征 | 频谱、包络、噪声比例、立体声特征 | 描述亮度、起音、衰减、宽度等，可在 CPU 处理 |
| 轻量模型 | EfficientAT `mn04_as` 或 `mn10_as` | 约 0.98M／4.88M 参数，提取通用音频向量；音色区分效果需实测 |
| 可选语义模型 | LAION-CLAP | 声音与文字匹配、语义搜索；更重，默认不要求 GPU |
| 偏好模型 | 正则化线性模型或轻量排序器 | 在固定音频特征上学习个人反馈，降低训练成本 |

分别提取不同音区和演奏片段的特征，再聚合为音色表示。比较时注意音高、响度和演奏长度对结果的影响；不能只把三段音频拼接后比较频谱就当作纯音色距离。

按照模型要求单独生成分析输入，例如重采样与声道转换；保留原始预览音。首次采用原模型验证，再评估 ONNX、量化等部署优化；不得在优化后默认推荐效果不变。

## 9. 历史音乐喜好与评分

喜欢一首歌可能来自旋律、人声、节奏或混音，不能直接推断用户喜欢其中所有音色。完整歌曲与孤立合成器单音也存在输入差异。因此历史歌曲作为初始参考，实际试听反馈用于校准。

推荐流程：

1. 用户导入本地音乐文件，并可圈选喜欢的片段。
2. 标记关注的用途，例如 Bass、Lead、Pad 或整体氛围。
3. 为不同参考片段建立多个偏好向量，保留不同方向。
4. 使用音频向量与常规特征寻找候选音色。
5. 用户对预览进行喜欢／不喜欢或两两比较。
6. 在本地训练轻量排序器，逐步提高实际反馈的权重。

建议提供参考相似度、用途匹配与个人偏好三个分量，综合权重在验证中确定。0–100 分表示相对推荐程度，不解释为客观音色质量或未经校准的喜欢概率。

初始可收集几十个预制反馈，之后持续学习；数量只是起点建议，不保证达到特定准确率。反馈不足时回退到相似搜索或常规排序，并保留一定推荐多样性。

音源分离为后续可选功能。Demucs 可分离人声、鼓、Bass 和其他伴奏，但不保证单独提取某个合成器。在基准设备上优先作为 CPU 后台任务，避免成为使用推荐功能的前置条件。

## 10. 本地运行、硬件与跨平台

- 音频、预制、向量和偏好反馈全部保存在本机，不调用云端推理接口。
- 提供包含本地依赖和已获许可模型文件的安装方式，关闭运行期自动下载与不必要联网。
- 断网测试覆盖扫描、加载、渲染、浏览、分析与排序；音源自身的授权机制需单独验证。
- 16GB 内存／2GB 显存是验证目标，不是已测得的性能保证。记录真实 CPU、内存峰值、模型占用与每预制耗时。
- 第一版默认串行音源渲染，分析用小批量与缓存；有数据后再开放有限并发。
- 支持设置预览目录和存储预算；存储量由音色数、预览时长和音频格式决定，扩展试听模板会增加占用。
- 为 macOS 复用扫描规则、数据库、分析与排序逻辑；插件二进制、界面操作、权限与打包单独适配。
- 验证 Apple Silicon／Intel 架构及对应插件支持，不预设 Windows 保存的插件状态可以跨平台直接恢复。

## 11. 开发阶段与验收

### 阶段 0：环境确认与样本集

- [ ] 确认 Serum 1／2、Vital、Sylenth1 的实际版本、插件格式、架构和离线授权方式。
- [ ] 准备可正常手动加载的代表性预制，包括银行、外部资源、慢起音、琶音、重复名称和失败样本。
- [ ] 记录少量人工演奏结果，作为加载和输出检查的参照。
- [ ] 验证宿主、模型与打包候选的版本及许可，固定原型依赖。

验收：环境清单与样本清单完整，可区分已支持、待验证和受限制的组合。

### 阶段 1：三个音源的批量渲染验证

- [ ] Vital 验证原生渲染及需要的插件加载方案。
- [ ] Serum 按版本验证预制切换与批量导出。
- [ ] Sylenth1 验证单预制与银行遍历。
- [ ] 生成三音区预览，并保存来源和演奏映射。
- [ ] 验证尾音、异步加载、资源缺失、连续切换、崩溃恢复。

验收：人工抽查的预览对应正确预制；银行每个已处理槽位可定位；失败原因可见；中断后能够继续。输出实测兼容矩阵，不以其他项目的说明替代测试。

### 阶段 2：可用的独立音色库

- [ ] 实现目录扫描、索引、浏览、播放、搜索、筛选与收藏。
- [ ] 实现进度、暂停、继续、失败重试和增量更新。
- [ ] 浏览时无需实例化音源。
- [ ] 完成基准设备上的较大样本批处理与断网验证。

验收：预览可直接播放，原预制可定位；重启不重复有效任务；界面保持可用；任务失败不拖垮整批处理。

### 阶段 3：音频相似搜索

- [ ] 提取常规特征和 EfficientAT 向量。
- [ ] 实现按音色找相似音色、按用途筛选。
- [ ] 检查音高、响度、混响和重复预制对排序的影响。
- [ ] 如有需求，再试验 CLAP 语义搜索。

验收：用户试听对比名称／标签搜索与向量搜索；记录相关性与耗时，决定模型是否值得保留。

### 阶段 4：个人偏好推荐

- [ ] 导入本地参考片段，记录关注用途。
- [ ] 收集预制反馈与两两比较，训练轻量排序器。
- [ ] 显示评分分量，并支持反馈不足时的回退。
- [ ] 与随机排序、简单参考相似度和常规收藏排序比较。

## 12. 许可与发布边界

技术实现和发行许可分别验证。DawDreamer 与 Vital 源码标明 GPLv3；当前 JUCE 提供 AGPLv3／商业双许可。所选版本及其依赖的许可应在确定发行方式时核对。

Vital 源码仓库另行说明了名称、服务访问与自带预制的限制，源码许可不能直接视为素材再分发许可。产品由用户指定已安装音源和已有预制，不自动打包商业插件或用户音色包。

旧 Serum 等组合可能涉及 VST2。不能仅因已有工具能够运行，就假设新产品可以随意取得或分发相关 SDK；应核对具体加载实现与许可。VST3 SDK 当前采用 MIT 许可，但不会替代各音源及其他组件的许可。
