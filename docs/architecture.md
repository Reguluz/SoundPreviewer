# SoundPreviewer 架构

更新日期：2026-10-22，当前为 0.8.2 开发版。项目依据 [项目计划](项目计划.md)，采用 C#、.NET 8 与 Avalonia 实现 Windows / macOS 共用桌面应用。原规划中的 Python / PySide6 是候选方案；当前 Python 限于可选插件宿主适配器。直接在 `main` 开发；patch 用于小修，minor 用于较大功能，major 须用户明确确认。`version-policy.json` 与 CI 限制批准的 major，`0.x` 发布始终为 prerelease。

当前交付包含可运行的音色库界面、索引、任务调度与渲染协议。真实合成器加载和演奏仍需逐版本验收；能够编译、通过基础设施测试或识别预制文件，都不能证明插件兼容。

## 项目职责

| 项目 / 目录 | 职责 |
| --- | --- |
| `SoundPreviewer.App` | Avalonia 共用音色列表、搜索与筛选、收藏和反馈、设置、任务控制、波形和本地播放、来源映射导出 |
| `SoundPreviewer.Core/Models` | 预制身份、来源、插件配置、试听模板、任务状态、音频指标、音区映射和 JSON 协议 |
| `SoundPreviewer.Core/Scanning` | 递归发现、格式检查、SHA256 变更检测、MD5 重复索引、来源重叠去重、银行条目索引 |
| `PluginScanService` / `PluginSelectionService` | 共享安装目录的只读 PE / 元数据 / 导出检查、位数与 VST3 包识别、已核对产品关联与版本选择 |
| `SoundPreviewer.Core/Storage` | 跨平台系统 SQLite 参数绑定、事务、版本化数据库、完整 JSON 元数据与设置 |
| `SoundPreviewer.Core/Services` | 有界渲染队列、进度、取消、有限重试、缓存与存储预算 |
| `PresetCategoryService` | 有界 JSON 名称分类规则、完整词 / 前缀匹配、独立 `CategoryTags` 与重新应用 |
| `PresetMetadataService` | 手工标签 / 分类、明确清空、恢复自动结果与旧有效字段兼容 |
| `PreviewStorageService` | 统一库目录迁移、SQLite 一致快照、音频路径重写和有界缓存清理 |
| `DuplicatePreviewService` | 校验相同内容及音区后补齐重复项的预览引用，保留各自的来源与个人记录 |
| `InitBaselineService` / `InitAudioComparer` | 无预制加载的启动基准、版本与模板身份校验、提交前的三音区严格近似比对 |
| `SoundPreviewer.Core/Audio` | 工作进程调用、进程生命周期、PCM 校验与指标、AAC / WAV 存储、拼接与重采样、WinMM / AudioQueue 本地试听 |
| `QuickPreviewAudio` | 双声道短窗响度检测、按 0.1–4 秒目标裁剪、边界静音压缩和淡化；默认每音 0.5 秒 |
| `SoundPreviewer.Worker` | 独立进程内执行 Vital 原生适配器，或转交实现协议的外部插件宿主 |
| `SoundPreviewer.Vst2Host` | 可选独立 x86 .NET 8 / VST.NET 进程，加载 Sylenth1 VST2 独立 FXP；不加入基础解决方案 |
| `scripts/renderers/dawdreamer_worker.py` | 可选 Python 宿主，用 DawDreamer 验证匹配架构的 VST2 单预制；发布时复制到工作进程的 `Renderers` 目录 |
| `tests/SoundPreviewer.Tests` | 无外部测试框架的回归检查；测试音频与测试工作进程只验证基础设施 |

```mermaid
flowchart LR
    Source[用户选择的音色来源] --> Scan[扫描与格式检查]
    Scan --> Store[(SQLite 索引)]
    Store --> Browser[Avalonia 浏览器]
    Browser --> Queue[有界任务队列]
    Queue --> Worker[独立工作进程]
    Worker --> Vital[Vital 原生程序]
    Worker --> External[可选外部插件宿主]
    Vital --> Validate[音频与映射校验]
    External --> Validate
    Validate --> Encode[AAC 压缩或保留 WAV]
    Encode --> Audio[已提交 M4A / WAV]
    Audio --> Store
    Audio --> Browser
```

浏览与播放读取已生成音频，不实例化插件。音色扫描、音频读取和渲染任务在后台运行，界面展示进度与结果。

试听使用 Windows `waveOut` 或 macOS `AudioQueue`，支持播放、暂停、继续、音区定位、拖动位置和独立音量。WAV / M4A 解码后在内存转换为 PCM16 播放，原文件保留不变。此实现不依赖 Windows Media Player；AAC 通过系统 Media Foundation 或 macOS afconvert 编解码，系统缺少对应组件时提示改选 WAV。

新 `PreviewTemplate` 默认 `NoteOrder=MiddleHighLow`，即中 → 高 → 低；`Pitches` 决定实际采集、拼接和 Notes 校验顺序。缺字段的旧 JSON 回退到 `LowMiddleHigh=0`，已生成音频按保存模板及真实 MIDI 映射播放和复用，不自动重排文件。顺序作为模板的一部分进入新缓存和启动基准身份。

界面以 C2 / C4 / C6 显示默认低 / 中 / 高音，协议仍保存 MIDI 36 / 60 / 84。`QuickPreviewSeconds` 默认 0.5、范围 0.1–4 秒；缺字段的旧模板仍解释为 0.5。默认值不额外改变旧缓存键；非默认快速时长参与新模板身份，实际裁剪与捕获上限按目标时长校验。

## 界面与分类

主音色表是唯一的逐音色任务视图，包含类别、尝试次数、最近任务结果 / 原因、生成时间、音源与适配器版本等可选列。列菜单更改可见性，横向滚动保留长字段；运行记录页不再复制音色表。`LastRenderOutcome` / `LastRenderMessage` 与可试听预览状态分开，因而强制生成失败但仍有旧 `Ready` / `NeedsReview` 预览时，仍可被「最近生成失败」查出。

搜索、音源、状态、来源、包、类别、标签及收藏条件以 AND 组合。来源使用来源 ID，类别与标签匹配完整条目，空值选项与「全部」分开。主生成入口与「生成筛选结果」共享当前视图快照，筛选后解析跨路径代表，默认校验并复用已有有效预览，只实际渲染缺失或失效部分；显式覆盖也限定同一快照。生成结束保留搜索和筛选条件，只有用户清除筛选或主动查看已生成时才切换范围。队列的已处理包含未配置与达到重试上限项目，完成不等同于全部成功。

设置采用五个内部子页：「目录」「已发现音源」「预览生成」「试听与存储」「分类规则」。「预览生成」将高级生成方式与「加载防错检查」横向组织，列表使用剩余高度和独立滚动，保留可调整的分隔条。设置页隐藏主播放台和闲置任务带，运行时保留任务进度；分类页仅显示规则专用保存入口。

库目录内的 `Config/preset-categories.json` 是可编辑的名称分类规则，首次缺失才从默认规则建立，不覆盖现存文件。规则仅支持关键词与前缀，不执行脚本或正则表达式；限制大小、深度和条目长度，失败保留上一份有效规则。扫描与显式重新分类共用此服务，先分析全部名称，再更新自动分类；手工分类保持有效，不修改稳定 ID、收藏、反馈或音频映射。

`PresetRecord.ManualTags` / `ManualCategories` 为 nullable 列表：`null` 表示使用自动结果，空列表表示用户明确清空。首次编辑保存 `AutomaticTags` / `AutomaticCategories` 快照，此后扫描与规则重算更新快照，`PresetMetadataService.Reset*` 恢复最近的自动结果。`Tags` / `CategoryTags` 始终镜像有效内容供既有读取方使用；源内容变化时创建新扫描候选也保留覆盖、快照与未知 JSON 字段。扩展字段保存在 schema 2 的原 JSON 中，不另建标签文件或改变缓存身份。

界面重新分类在后台克隆记录、应用规则并事务持久化，成功后才在界面线程合并 `CategoryTags` 与刷新筛选选项。取消或写入失败不先改变可见记录，避免出现界面新分类与磁盘旧分类不同步。

## 身份与来源

明确指定音源的来源沿用音源种类、规范化源文件路径、包内路径和可选银行槽位生成的身份。自动识别来源以物理文件与包内位置保持身份，后续自动纠正或手动指定音源不改变已有记录 ID。名称用于展示与搜索，重复名称不会合并不同文件。`SourceFolder.AutoDetect` 默认关闭，使旧版设置继续按指定音源扫描；新增混合目录可开启自动识别。

自动识别采用独有扩展名：`.vital` / `.vitalbank` 属于 Vital，`.SerumPreset` 属于 Serum 2。共享 VST 格式只接受已核对的完整文件头产品 ID：`XfsX` 为 Serum 家族、`syl1` 为 Sylenth1。已核对的产品 ID 优先于误放的目录名称，并在 `DetectionReason` 中保留冲突说明；最近且在配置根目录以内的完整目录词可将 Serum 家族细分为 Serum 2。未知 / 缺失产品 ID、版本词冲突和不可靠共享格式进入 `Unknown` / `Unidentified`，不根据子字符串、文件名或共用扩展名猜测可渲染音源。

明确音源的目录优先于重叠的自动识别目录。`ScanService.AssignSynth` 保持记录 ID、收藏、反馈与个人标签，记录手动分类；音源变化时清除预览元数据、缓存和重试历史。此分类随后续扫描保存，不会被目录或文件头重新覆盖；银行仍保持不支持渲染。识别依据与标签持久化供界面检索和核对，识别归属不构成插件实际加载验收。

每次扫描在同一次读取中计算支持源文件的 SHA256 与 MD5，能够发现文件大小与修改时间均未变化的内容修改。相同身份内容变更后，收藏、喜欢 / 不喜欢反馈、个人标签和手动分类保留，旧预览元数据与重试计数失效；SHA256 未变化的旧记录也会回填 MD5。重叠来源按身份去重；关闭、不可访问或未能完整扫描的来源不会使已有记录被误判为丢失。扫描跳过重解析点，不跟随目录链接。

`ContentMd5` 保存完整物理源文件的 MD5。`PresetIndex.RebuildDuplicates` 按 MD5、音源、区分大小写的包内路径和银行槽位分组，保留所有路径记录，只通过 `DuplicateOfId` 指向代表项。默认浏览与队列隐藏副本，不删除用户文件、收藏或反馈。代表优先选择启用且可访问来源，再考虑完整有效预览和个人反馈；失踪代表会被可用副本替代。复用旧代表音频还须匹配 SHA256、通过音频、保存模板与三音区映射检查，保留新代表自己的来源和反馈，并标为待确认。MD5 用于索引去重，不取代 SHA256 和实际渲染验证。

Vital `.vital` 检查 JSON 和 `settings` 对象。`.vitalbank` 只读取 ZIP，保留 `.vital` 条目的内部路径，指纹同时包含整个包的哈希，以覆盖包内资源变更。它不解压资源、不宣称条目可直接加载，并标记为 `Unsupported`。Sylenth1 `.fxb` 记录为不透明银行，不根据文件名或推测数量伪造槽位。FXP 检查 VST 文件头；该检查不能确认实际插件产品或授权。

独立预制引用的外部采样、波表与相对资源还没有完整的依赖清单；这些资源的变化尚不能全部自动使缓存失效。真实加载检查和资源验收属于后续适配工作。

## 插件目录

`AppSettings.PluginDirectories` 保存共享安装目录，`DiscoveredPlugins` 保存可核对的发现结果；旧设置默认为空，不改变既有插件配置。扫描 `.dll`、`.vst3` 文件 / 包和 Vital 独立程序，只读取 PE 架构、版本资源及 VST 入口导出，不执行插件。VST3 包分别保存用户选择的外层路径与内部实际二进制路径。无必要导出的普通 DLL 不作为插件，已知 SerumFX 效果器不作为乐器；只有产品元数据与结构证据相符时才关联实际音源，否则候选保持 `Unknown`。

自动关联选择当前平台与架构兼容的已识别候选；若 Windows 发行目录带有独立 x86 宿主，也允许 Sylenth1 x86 VST2。按当前格式偏好与版本排序，保留仍有效的用户 DLL / VST3 包选择。Vital 独立程序只能自动填入未配置或原生后端；已有自定义外部渲染程序不能被扫描替换。插件路径、发现版本与「预览生成 → 生成方式（高级）」中的宿主程序是不同字段。手动选择版本仍须满足宿主位数和格式，发现或关联成功不代表实际插件可渲染。

显式从 Vital 原生切换至 VST 会清除 CLI 程序及其指纹，将后端转为未配置；显式选回独立程序会恢复原生后端，清除旧 VST 路径及指纹，避免版本记录与实际执行的程序不一致。

`PluginSelectionService.RefreshBundledHost` 只在当前发行带有可用内置宿主时，迁移 Sylenth1 / ExternalWorker 中文件名精确为 `SoundPreviewer.Vst2Host.exe`、父目录精确为 `Vst2Host-x86` 的旧路径（大小写不敏感）。迁移清除旧可执行文件指纹和基准定位，保留插件路径、指纹及实际版本；相同当前路径为幂等操作，自定义程序和其他配置不受影响。此步骤不执行插件。

## 存储与缓存

0.7.1 正式运行固定使用 `ApplicationPaths.DefaultPreviewDirectory`：Windows 为程序目录下的 `Preview`，macOS 为 `.app` 旁的 `Preview`，不写入签名包内。`ApplicationDirectory` 仍指向实际程序与资源目录，`PortableApplicationDirectory` 用于确定数据根。`library.db`、运行日志、缓存、加载防错参照、`Config` 与手工元数据保存在同一库根；设置不能改为任意外部输出目录。程序目录不可写时明确报错，不静默回退到用户目录。普通历史 `--data-directory` 仅指定导入来源，`--smoke-test --data-directory` 保留隔离测试与诊断；内部 `--test-installed-storage` 运行真实启动的同一迁移流程再执行 UI 自检。详见[数据与升级](cross-platform.md#数据与升级)。

旧定位文件、旧用户库和 `local-data` 仅用于确定首次迁移来源。目标 `Preview` 已有库时不使用旧库覆盖，只归并目标自身引用的外部音频与加载防错参照；需要兼容旧库时，先复制一致快照、个人记录和规则及引用预览，校验后在目标库更新路径，再使用目标。旧数据库、规则与音频保留作回退备份，不因定位记录或旧 `PreviewDirectory` 设置而续写原位置。

设置提供「打开 Preview 文件夹」「清空预览」「导入旧版音色库」。手动导入经界面确认后，Core 先在独立暂存目录复制全部引用音频与源数据库，并验证已知记录及设置字段可读；完成后才将当前完整 Preview 原子改名为同一程序目录下 `Preview-before-import-*`，再发布暂存库，不合并。失败且目标空缺时尽量原子恢复原名，并明确显示备份位置。备份内仍有原 Preview 的绝对路径，拒绝将其作为普通异名源直接导入；恢复需退出并备份当前 Preview，再把恢复目录还原名 Preview。

存储迁移先建立包含已提交 WAL 页的 SQLite 快照，复制 `Config` 和必要音频并校验哈希，再在目标库中事务保存设置与路径。旧库迁入固定 Preview 时保留试听与基准映射，并保留全部原始数据库、规则和音频作为回退备份。独立「清空预览」只处理当前记录或基准明确引用、可确认独占且不经链接的缓存；共享目录、外部音频、源文件和未知音频 / 基准保留并报告，不凭哈希命名清理孤立文件。清理保留标签、分类、收藏与源记录，不递归删除库根，也不保证目录完全为空。

SQLite schema 0/1 升级前生成一致备份，备份或迁移失败即中止、回滚；schema 2 保持不变，未知更高结构拒绝打开。首次导入只升级暂存副本，源数据库、schema、WAL 中的已提交记录及原文件保留；记录与应用设置的未知 JSON 字段也保留。缺失的已生成音频保留原映射并提示，不自动清空。程序升级不单因应用版本改变缓存键，既有有效预览仍可复用。

迁移读取原库时保持只读。已关闭且没有 WAL / SHM 辅助文件的 WAL 主库，先在安装目录内制作经前后哈希及辅助文件存在性检查的私有输入，再读取该副本；活动 WAL 仍由 SQLite backup API 读取提交快照。仅将私有快照转为 `journal_mode=DELETE` 并检查完整性，使备份可独立读取、复制，避免 Mac 只读连接初始化辅助文件失败；正常运行库仍使用 WAL。依据 [SQLite 的只读 WAL 条件与独立快照建议](https://www.sqlite.org/wal.html#read_only_databases)。

数据库使用 Windows 提供的 `winsqlite3.dll` 或 macOS 提供的 `/usr/lib/libsqlite3.dylib`，采用 UTF8 参数绑定、WAL 和事务。`user_version` 标记数据库结构版本；v2 在 v1 基础上增补 MD5、重复代表列和索引，保留旧记录与设置。预制与设置以完整 JSON 保存，另有身份、来源、状态和反馈列供索引使用。`FindByMd5` 验证十六进制输入并进行参数绑定、大小写不敏感的索引检索。收藏、反馈时间、渲染模板、插件版本、实际音区时长及指标均随记录持久化。

0.8.2 启动时对当前 Preview 轻量检查 schema、保存的输出根与音频路径；已就位库直接打开主窗口，不创建迁移窗口、暂存库或数据库快照。没有新增迁移标记文件或 schema。旧 schema、搬移后的旧根、现存的外部预览或基准引用仍走原安全迁移；缺失历史音频保留原引用，后来重新可用时再迁入。正常渲染与个人元数据修改不触发重复迁移。

新生成的缓存键结合预制内容、银行身份、音源配置、可执行文件与插件文件哈希、试听模板和适配器版本；VST3 包的插件指纹包括已发现的实际内部二进制。默认生成先根据记录保存的模板校验已有 WAV / M4A、采样率、适配器版本与完整三音区映射，在当前插件配置检查和重试限制之前跳过有效预览。因此模板或插件配置变化不会自动重渲染；`forceRegenerate` 显式跳过复用，源内容与归属变更仍由扫描失效旧映射。分析模型尚未接入；未来模型版本变化应只重算分析结果，不使真实预览音频无故重渲染。

任务先在最终预览目录的同卷私有目录写入请求、结果与 WAV。桌面端完成原始音频、映射及启动声音参照校验后，按设置编码 AAC 或保留 WAV，再移动到最终缓存路径，避免将半成品当作已完成预览。每项提交立即持久化后再进入下一项；停止会结束当前进程树，无旧有效预览的当前项转为待处理并撤回本次尝试计数，已完成与未触及项保留。强制生成仅在当前项开始时备份其旧有效映射，取消或失败恢复该映射，不预先清空整个音色库。

`AppSettings.PreviewFormat` 缺字段默认 AAC；编码格式不进入缓存或模板身份。AAC-LC 128 kbps 保留 44100 / 48000 Hz 和声道，同文件 MP4 uuid 原子保存原始帧数与绑定媒体及元数据的 SHA256；解码限制时长、大小和尾部补齐，不猜测裁去开头。声音参照仍为无损 WAV。主动压缩服务只更新本库可确认归属的引用 WAV，发布 M4A 并事务更新全部匹配引用后才批量重新检查并清理原文件，保留源文件、基准、外部或共享音频、未知文件、收藏及确认状态。取消后保留已完成结果；旧版程序回退使用升级前备份。

音频提交与数据库提交不属于同一事务；启动恢复发现中断任务时，完整有效旧 WAV / M4A、保存模板和三音区映射可保留并转为待确认，否则转回待处理并清空无效派生映射，原尝试历史保留。已经生成但尚未索引的文件可能保留，自动清理策略尚未实现。

## 渲染与校验

一个任务调用一个独立工作进程，默认按机型和内存目标调度。进程通过 JSON 的 `RenderRequest` / `RenderResult` 协议交换来源、插件、模板、目标路径、音区映射和结果。Windows Job Object 和 macOS 独立进程组用于超时、取消和退出时结束渲染子进程。详细参数与实际限制见 [渲染后端说明](rendering.md)。

0.8.2 的执行设置保留原 `Backend`，以独立的只读 `RenderReadiness` 快照传给本轮队列，不再将预检失败的已选后端改成 `Unconfigured`。有效旧预览优先复用；真正未选方式计入 `Unconfigured`，已配置但检查失败计入 `Unavailable`，汇总按音源及具体原因分组。跳过原因批量更新已存在记录的最近任务结果，不新增临时输入、不消耗尝试次数，也不清空已有音频、确认文字或配置。该执行信息不进入缓存键或持久设置。

`AppSettings.MaxParallelRenders` 支持 0（自动）与 1 / 2 / 4 / 8 / 16。新设置默认自动，旧 JSON 缺字段仍解释为 1，已有显式选择保留。自动按物理核数向下选择档位；内存探针统计当前父进程及 Worker、Python / 原生宿主后代的 RSS。0.7.5 面向 16 GB 及以上内存电脑，将总 RSS 目标设为 **4 GiB（4096 MiB）**：实际占用达到 **3.75 GiB（3840 MiB）** 时暂停新增，超过 4 GiB 或连续无法完整监测则取消并收束。队列先校准各音源开销，再按独立 Worker PID 归属预留内存；启动条件仍要求实际占用、现有任务预测预留和新任务预测共同容纳于暂停阈值内，因此可能提前限流，不保证占满预算或达到 8 条并行。100ms 采样不是操作系统硬配额，瞬时峰值仍可能越过目标；预算调整不改变音频缓存键或数据库 schema 2。

相同音源仍须显式启用 `PluginConfiguration.AllowParallelRendering`，缺字段默认 false，重新关联不同插件或版本会撤销许可。设置快照、同缓存键任务合并、单次声音参照准备、空间预留和集中提交由父进程协调，Worker 使用独立进程和新实例。调度设置不进入音频缓存或声音参照身份。停止会收束所有在飞任务，已完成的提交继续入库；手动建立声音参照也复用同一内存保护会话。详细验证见 [并行方案](parallel-rendering.md)。

0.7.0 的待执行任务按音源首次出现顺序稳定分组，同源内保持输入顺序。当前音源可并行时优先继续该组，后续未知音源在边界独立校准；当前音源禁止多实例且空槽无法填满时，才在空闲边界提前校准后组以供异源补位。每项仍使用新 Worker / 插件实例，此排序不代表插件常驻，也未单独量化加载时间收益。

App 的音色拖出使用 Avalonia 系统 `DataTransfer` 文件项，只提供独立原音色的路径和 `Copy` 效果，不提供预览 WAV，不改写来源或数据库。包内路径、银行槽位、待识别及缺失来源会阻止操作。接收端决定是否加载；DAW 自动建轨及实例化尚无通用协议适配，官方依据与验证范围见 [DAW 音色传递](daw-transfer.md)。

Vital 原生路径实现了三次单音渲染、音频拼接和实际演奏参数记录，但原生 CLI 没有可依赖的预制加载成功反馈。因此原生渲染结果进入待确认状态，须人工检查音色对应关系与外部资源。

Serum / Sylenth1 通过可选外部宿主协议接入。DawDreamer 后端使用用户指定的 Python 和插件路径，支持匹配架构的 Serum 1 / Sylenth1 独立 VST2 FXP，以及 Serum 2 VST3 原生 `.SerumPreset` 的状态转换与加载回读；旧 FXP 不直接交给 Serum 2 VST3。独立 VST.NET 后端只适配 Sylenth1 x86 VST2 FXP。桥接固定 DawDreamer 0.8.3 / NumPy 1.26.4，提供运行库检查和空宿主自检。真实插件的历史样本、版本与人工确认边界保持在[渲染记录](rendering.md)，不能据第三方支持声明或测试通过扩大兼容范围。

WAV 校验检查格式、帧边界、采样率、长度、非有限值与三音区时间范围。峰值、RMS、过零率及每音区指标用于排查静音和接近削波的输出；它们不是完整音色特征、模型向量或偏好评分。静音与削波线索进入待确认，异常值、截断文件或无效映射不提交。

界面的「加载防错检查」在协议中仍使用 `RenderRequest.IsInitializationBaseline`：宿主建立新实例而不加载任何预制，记录启动声音，防止加载失败后将默认声音误存为目标音色。元数据绑定插件 / 宿主指纹、实际版本、模板和策略，保存独立 WAV 与音区映射。Serum 1 / Serum 2 / Sylenth1 的 DawDreamer 后端及内置 Sylenth1 x86 宿主提供该协议；Vital CLI 和未适配后端不提供此保护。自动建立参照通常不需用户手动操作；声音不稳定时不能宣称可比对，只有下述已支持精确状态回读的组合可改用替代检查。真实版本验收仍以各轮样本记录为准。

历史 Windows 单样本记录：Serum 1.334 x64 / DawDreamer 与 Sylenth1 2.2.1.2 x86 / 内置宿主完成 v2 中高低顺序的自动检查，独立启动输出均命中 3/3 参考，正常 FXP 均为 0/3；两份正常音频低音量设备播放完成。该轮未覆盖批量或新的人工音色身份确认。Serum 1.334 x64 与 Sylenth1 2.2.1.2 x86 更早的各一个真实 FXP 已生成、播放，用户确认三音区正常；这两轮确认范围分别保留，不合并为更大兼容性结论。

可用基准对新输出执行三音区波形相关、包络、频谱与响度的多条件检查，不能仅凭名称或单一频谱判定。严格匹配默认启动声音的结果在原子移动前被拒绝，记录最近失败；旧有效预览不被覆盖。无法建立有效检查时明确失败，不静默宣称已启用声音保护。默认复用既有完整预览仍先于新基准流程，旧缓存不会被追溯宣称已通过此检查。详见 [基准支持与验收边界](rendering.md#默认启动音色基准)。

0.7.2 对内置 Sylenth1 x86 宿主提供显式 `VerifiedPresetLoad` 模式：三份真实参照均有效、已知 v2 宿主仅因启动声音波动而不能校准时，保留参照与身份记录，`CanCompare` 仍为 false。提交目标输出前必须具有已知方案、目标源 SHA256、完整三音区顺序和原生适配器版本对应的精确状态回读证明。Chunk 须逐字节一致，参数型 FXP 须逐参数回读；快速预览的任何采集轮缺少证明均不能获得最终证明。未知宿主、损坏参照、其他生成失败、缺失或错误证明均不能走此路径。原声音阈值、缓存复用顺序与 SQLite schema 2 保持不变。

`startup-audio-comparison-v2` 使用三份独立原始参考，对三音区分别作受固定硬边界限制的漂移校准；参考两两不在硬边界内则校准失败，不产生可用声音比对结果。候选须整体匹配至少两份参考的全部三个音区，不能把不同参考中各自匹配的音区拼成通过结果。短于四分之一秒的参考只采用原严格比较，不扩大容差。

## 扩展边界

本版本没有 EfficientAT / CLAP、相似音色搜索、参考歌曲导入、个人推荐训练、OCR / 视觉加载流程或自定义 MIDI 模板。收藏和反馈作为真实用户数据保留，可供后续本地分析使用。

App、Core、Worker 与测试共同使用 `net8.0`。App 的 Avalonia XAML、事件处理与界面模型在两端共用；平台差异收敛在原生音频、SQLite 加载、插件元数据与进程隔离。可选 x86 VST.NET 宿主仍单独使用 Windows 目标，不进入 macOS 发布。详见 [双平台实现与验证](cross-platform.md)。

桌面界面使用 Avalonia、Fluent 主题和 DataGrid NuGet 包。商业音源、用户音色包、Python 宿主依赖和模型权重不随当前应用捆绑。发布前还需核对所选宿主、源码、SDK、模型及素材的实际版本和再分发许可。
