1.0.0 用户说明源文件位于英文目录 `UserGuide/*.md`，正文、截图和交叉链接随 App 构建与发布复制。Windows 点击右下角书本图标打开 `UserGuide/SoundPreviewer.chm`；macOS 打开 Markdown 首页。`scripts/Build-UserGuide.ps1` 使用 PowerShell 内置 Markdown 转换器及固定版本的 Microsoft HTML Help 编译器；仅在临时构建目录生成 HTML，随后编译并解包比对九个章节和全部图片。编译器从 Microsoft 官方 Visual Studio 包地址下载并校验 SHA-256，不写入系统目录或注册组件。首次 Windows 构建前运行 `pwsh -File scripts/Build-UserGuide.ps1`；生成的 CHM 在 `artifacts/user-guide`，构建及发布自动复制。CI 先编译手册，再将同一 CHM 分发到三个平台作业。`scripts/Test-UserGuide.ps1` 检查 Markdown 链接、锚点和图片，发布与打包检查额外要求合法 CHM。用户已明确要求版本升至 1.0.0，`version-policy.json` 同步批准 major 1。

0.11.0 引入 `MetadataCatalog`：根目录分类/标签 JSON 提供固定数值 `Id`、目录 `CatalogId`、名称、别名和分语言文本；记录保存编号，schema 2 及缓存键不变。遗留字符串继续保留兼容，首次编号迁移前备份数据库。设置内的目录快照支持缺失文件恢复与跨库导入，目录身份不同则从来源快照重新对应，避免同号串项。外部编辑冲突和损坏 JSON 不覆盖。分类/标签编辑使用虚拟化的固定高度列表，新扫描不再自动生成音源、扩展名标签；手工覆盖继续生效。默认规则增加 Chord，并为已有默认规则保留升级前副本。

`LanguageService` 从 `language/*.json` 读取首个 `languageName` 及 `strings`，Avalonia 动态资源与显示绑定在切换时更新，分类/标签可独立选语言。持久化状态和用户名称、路径保持原值；参数化提示保留捕获的动态值。完整用户文档见操作说明；历史 0.x 均为预发行，当前版本以 Version.props 为准。

0.10.3 为 Serum 的启动声音匹配增加疑似加载失败说明及版本核对建议，历史匹配错误只在显示及复制时解释，不改库中原文。现有宿主未提供弹窗文本；Serum 2 的版本更新提示基于预制元数据和已核对的实际插件状态，配置版本不一致时不冒称插件过旧。匹配算法、阈值、缓存身份、一次拒绝及失败保留旧音频的行为沿用原逻辑。

0.10.2 修复 Sylenth1 目标音色已在槽位时的状态未变误判；只在完整回读匹配目标时放行。已核对的旧 192 参数序列化格式由独立实例转换为标准状态，再逐音区核对名称与完整状态，使用单独的转换核验证明和标准状态 SHA256；快速预览延长采集须保持同一证明与状态指纹。未知格式、转换无变化、名称不符或参数不一致仍拒绝提交。生成进度、音色详情和运行记录可复制完整描述，结果复制不会写回音色元数据。

0.9.0 将确认的 Material 3 视觉稿落地至 Avalonia 动态资源，`AppSettings.Appearance` 保存主题模式、预设和自定义颜色，旧库缺字段回退默认，未知 JSON 继续保留。配色对话框只在应用后写库，取消还原全局预览。七组筛选计数使用同一搜索和字段匹配规则，计算某组时忽略该组选择，保留其他组约束及全局重复项开关；分类与标签按项分别计数，同一条音色在同一项只计一次。

当前内存预算由 `AppSettings.MemoryBudgetGiB` 保存，取值 1–16，缺字段默认为 4。每批队列及手动声音参照取不可变预算快照，准入阈值为预算减 256 MiB，监测、预测预留和进度均采用同一预算。以下 0.7.x 的固定预算说明保留为历史记录。

预览引用在 SQLite 中按 Preview 根保存相对路径：`PreviewPath`、`PreviewDirectory`（`.`）、`InitBaselinePath`，以及声音参照 JSON 的音频路径。`LibraryStore` 读取时解析为库根内的运行路径，写入时恢复相对格式，工作目录不参与解析。旧绝对路径通过启动迁移保留原件并兼容转换，库内相对路径拒绝越界与链接；整体搬移不改变音频字节、缓存键或个人元数据。

0.6.0 引入自动及 1 / 2 / 4 / 8 / 16 条独立 Worker，按物理核心与进程树内存观测调度，当时总 RSS 预算为 2 GiB。0.7.5 按 16 GB 及以上内存的电脑使用需求，将主程序及全部生成后代的总 RSS 目标提高至 **4 GiB（4096 MiB）**，**3.75 GiB（3840 MiB）** 暂停新增任务，超过 4 GiB 取消本批并保留已完成预览。实际占用与预测预留共同决定能否启动，可能在低于暂停阈值时限流，不保证吃满预算或达到 8 条并行。100ms 采样保护不等于操作系统硬配额。并行档位、缓存键与数据库 schema 2 不变，测试和历史测速入口见 [并行方案](docs/parallel-rendering.md)。

Windows / macOS 本地合成器预制音色库，使用 C#、.NET 8 和 Avalonia 开发。两端共用完整界面与业务核心，使用各自的原生音频输出。SQLite 保存来源、预览映射、任务状态与个人反馈，浏览试听不需要启动 DAW。界面使用 Avalonia NuGet 包，音色库与渲染在本地运行，不调用云端服务。

0.8.4 开发版（2026-10-23）将预览与声音参照的持久路径改为相对于当前安装目录的 Preview，并增加 1–16 GiB 可调内存预算，默认 4 GiB。旧绝对路径兼容转换，移动安装目录后继续读取本地已有预览；旧音频、缓存键和个人元数据保留。

0.8.3 修正「显示重复项」关闭后，副本仍因匹配筛选而出现的问题。列表严格隐藏所有 `DuplicateOfId` 非空的记录；不再在筛选范围中另选副本替代保留项。显式显示副本时仍解析到同一主记录生成。

0.8.2 修正已配置但检查未通过时误报「未配置」：执行保留原后端选择，独立传递本轮可用性检查；区分「未选择生成方式」与「已配置，暂不可用」，在汇总及对应音色记录保留具体原因，仍优先复用有效旧预览。

已就位的 Preview 启动时直接打开，不再重复显示迁移窗口或创建整库快照；导入、目录搬移及需要归一化的旧路径继续使用安全迁移。扫描和手动关联后也会补齐已准备的私有生成环境，支持先准备环境、后安装或扫描插件的操作顺序。

0.8.1 新预览默认在原始 PCM 校验后压缩为 AAC-LC 128 kbps / M4A，保留 44.1 / 48 kHz、立体声及精确音区时序；支持旧 WAV 复用及主动批量压缩，不改变缓存键与 schema 2。Windows 使用 Media Foundation，macOS 使用系统 afconvert，不捆绑 FFmpeg；NAudio 2.2.1 许可随包发布。压缩失败或停止保留未完成原预览，元数据和声音参照保持原样。

0.8.0 增加私有 uv / CPython / DawDreamer 一键准备：无需系统 Python，固定依赖、缓存与运行库均保存在应用旁；相对运行时清单支持整体移动和离线复用，保留已有后端、自选环境、有效旧预览及 schema 2。Sushi 保留本地研究入口，不捆绑公开分发，范围见 [宿主研究](docs/headless-host-research.md)。沿用空格键重播、Preview / Config 缺失初始化、同音源优先、自动并行及 4 GiB 内存目标。Windows 与 macOS 共用扫描、检索、收藏、反馈、播放、任务恢复和渲染功能，包含 Serum 2 VST3 原生预制加载与 Spire 索引。真实音源支持范围见 [渲染验证记录](docs/rendering.md)；DAW 接收方式见 [音色传递](docs/daw-transfer.md)。AI 向量搜索、个人推荐与 FXB 银行槽位遍历尚未实现。

## 启动

支持 Windows 10/11、macOS（Apple Silicon / Intel）。测试朋友请优先使用 [GitHub Releases](https://github.com/Reguluz/SoundPreviewer/releases) 中对应平台的安装包；尚未发布时可从 [Actions](https://github.com/Reguluz/SoundPreviewer/actions) 的成功构建下载测试包。发布版包含 .NET 运行时。安装与发布步骤见 [版本发布](docs/releases.md)。从源码构建需要 .NET 8 SDK，仓库固定 SDK 8.0.425。

首次完整解压无需先复制 Preview 或 Config，缺失时可新建必要配置和空库。已有 Preview 继续读取，已有 Config 保留；直接在原目录升级并保留这两者是延续个人数据的推荐方式，不是启动前置条件。

双击仓库中的 `Start-SoundPreviewer.cmd`，或使用下面的启动命令。

```powershell
powershell -ExecutionPolicy Bypass -File .\Start-SoundPreviewer.ps1
```

macOS 从源码双击 `Start-SoundPreviewer.command`，或运行 `./Start-SoundPreviewer.command`。

正式运行将数据库、日志、预览音频、标签与可编辑分类规则固定保存到程序旁的 `Preview`，安装版与 Portable 相同。Windows 位于 `SoundPreviewer.exe` 同目录；macOS 位于 `SoundPreviewer.app` 旁，不写入 bundle。请将应用放在可写的独立文件夹，例如 Mac 的 `~/Applications/SoundPreviewer`；不可写时明确报错，不回退到用户目录。更新时保留 `Preview`，窗口版本提示和设置中的数据目录可核对实际位置。

旧定位文件、旧用户目录和便携 `local-data` 用于查找首次兼容迁移来源，不再让正式程序续写旧位置。迁入当前程序旁的 `Preview` 前，先建立一致数据库快照、复制个人记录与规则及引用音频并校验，旧数据库和旧音频保留作回退备份；已有 `Preview` 保持自身记录，只归并它引用的外部音频和声音参照。设置提供「打开 Preview 文件夹」「清空预览」「导入旧版音色库」，不再提供任意外部输出目录。手动导入须确认，先在暂存目录复制校验所选库与引用音频，并验证记录、设置可读，再将当前完整 Preview 原子改名为程序旁 `Preview-before-import-*` 后发布暂存库，不合并；失败且目标空缺时尽量原子恢复原名并明确备份位置。较早版本的此类备份可能保留原 Preview 绝对路径，恢复须先退出并备份当前 Preview，再将备份目录还原为 Preview，不能直接作为异名导入来源。普通历史 `--data-directory` 参数仅指定导入来源；`--smoke-test --data-directory` 保留给构建、测试及隔离诊断，新内部 `--test-installed-storage` 入口运行正式启动的同一迁移流程再执行 UI 自检。详见 [升级与缓存](docs/cross-platform.md#数据与升级)。

Portable 表示免安装，升级可在原目录替换程序文件。移动程序前退出并备份，连同 `Preview` 一起保留；原音色、插件和可选 Python 环境的绝对路径仍须核对。

## 配置与使用

1. 在「音源与设置」中选择「自动识别（混合音色包）」并添加整个音色包目录，无需按音源拆分子目录。也可明确选择单一音源；已有目录保留原来的指定方式，可选中后点击「自动识别此目录」切换。
2. 点击主工具栏「扫描音源」，在「已发现音源」查看结果；「扫描音色」用于更新预制目录，两者独立。首次使用预填系统与用户的音源安装位置，空列表扫描会恢复默认位置；可在设置「目录」中追加自定义安装目录。macOS 包括系统 / 用户的 VST、VST3 和 Applications 目录，支持识别已安装的 Vital `.app`；不可访问位置会保留并显示提示。「已发现音源」保留版本、格式、架构和实际二进制路径。匹配当前平台与架构的已识别候选可自动关联，也可选中后点击「使用选中版本」。包含可选独立 x86 宿主的 Windows 版本也可自动关联 Sylenth1 x86 VST2；已有自定义外部渲染器会保留，未知候选和其他 x86 插件不会自动启用。
3. 已关联的 Vital 独立程序可使用原生方式。快速模式使用真实原生采集参数，再按设定时长截取试听；需要完整按键与尾音时，点击「采用 Vital 原生参数」切换到固定时长。已有的有效版本选择会保留，自动扫描不会擅自替换用户配置的外部渲染器。
4. 「预览生成 → 生成方式（高级）」中可设置外部渲染程序或具备宿主依赖的 Python，不等同于插件路径。可选 DawDreamer 桥接须匹配 Python 与插件架构；Serum 1 / Sylenth1 使用 VST2，Serum 2 使用 VST3 和原生 `.SerumPreset`。Serum 2 的旧 `.fxp` 须先在 Serum 2 中导入并另存为原生格式。Apple Silicon 的 Serum 2 2.0.23 历史样本已通过加载后状态回读、完整队列及加载防错检查，仍待人工核对音色和外部资源。依赖安装、自检与真实兼容边界见渲染记录。
5. 保存三音区音名、BPM 和存储预算，然后扫描预制目录并生成预览。默认开启「快速预览」，每音时长默认 0.5 秒，可设 0.1–4 秒；弱音或慢起音自动有界延长采集，裁去两端明显静音，三个片段直接相接。关闭快速预览可使用自定义按键时长及尾音。
6. 音高设置显示低音 C2、中音 C4、高音 C6，内部对应 MIDI 36 / 60 / 84。新生成默认按中 → 高 → 低排列；音区按钮按实际映射定位。旧预览按自身保存的顺序播放，不自动重排或失效。待确认预览仍须核对音色与外部资源。

### 筛选、记录与分类

1. **组合筛选**：音色库按搜索、音源、状态、来源目录、音色包、类别、标签和收藏状态同时筛选，条件之间为 AND。顶部「生成 / 继续」与「生成筛选结果」捕获同一当前视图，先筛选再解析跨路径重复代表；默认校验复用已有有效 WAV / M4A，只实际渲染缺失或失效预览，完成后保留筛选条件。
2. **统一音色列表**：默认显示音色名称、音源、类别、状态与收藏；0.10.1 扩大音源、类别、收藏的默认列宽，移除「尝试」「最近任务」两列。失败原因、生成时间、版本、时长等可通过「列」按钮或表头菜单选择显示，支持横向滚动；最近任务结果仍可在音色详情查看。「运行记录」只保留日志与维护操作。「最近生成失败」还能找到本轮失败但保留了旧有效预览的音色。
3. **设置子页**：「目录」「已发现音源」「预览生成」「试听与存储」「分类规则」分开显示。目录与生成方式区可调整左右宽度，列表随可用高度伸展；设置页隐藏主播放台，任务运行时仍显示进度。
4. **加载防错检查**：有些音源加载失败后仍会播放默认声音。支持的宿主会记录刚启动、未加载任何预制时的三音区声音作参照，防止把它误存成目标音色，通常无需手动操作。代码支持 Serum 1 / Serum 2 / Sylenth1 的 DawDreamer 后端及内置 Sylenth1 x86 宿主；Vital CLI 和未适配宿主不提供此保护。三份独立参考只在固定边界内校准漂移，候选须完整匹配至少两份参考的三个音区才被拒绝；参考不稳定则明确失败。拒绝新结果时保留旧有效预览，已有缓存仍默认复用。插件、模板或策略变化后须重建参照；各真实样本的历史检查结果见[实测范围](docs/rendering.md#默认启动音色基准)。
5. **可编辑分类规则**：音色库数据目录内的 `Config/preset-categories.json` 保存名称关键词与前缀规则，默认文件只在首次缺失时建立。分类页可编辑 JSON、重新载入、保存并应用，或重新应用已保存规则；也可用外部编辑器修改文件。类别与来源识别标签分开保存，一个音色可有多个类别。无效规则不清空已有分类，重新分类不改变预制身份、收藏、反馈或预览文件。
6. **手工标签与分类**：选中音色后，在详情中用逗号或换行编辑并保存；保存空内容表示明确清空。重新扫描、源文件内容变化及分类规则重算均保留手工编辑。「恢复自动」解除手工覆盖，采用最近一次扫描或规则计算的结果；收藏、反馈与有效缓存不因编辑标签而改变。

默认跳过已有完整、有效预览，包括以前的长预览，即使修改了模板或插件配置。勾选顶部「全量重渲染（覆盖）」后点击「生成 / 继续」，会重新处理当前筛选内可生成的代表音色；新结果校验成功后替换预览映射，同一缓存路径原子覆盖。该选项只作用于本次操作，重复副本不单独渲染。未选择生成方式或已配置但暂不可用的项目计入已处理，保留原音色状态与尝试次数；结束信息区分成功与跳过并给出具体原因。

任务运行中可点击「停止」，立即结束当前渲染进程，已完成结果逐项保存。下次生成只继续未完成项。强制生成不会预先清空旧音频；当前项停止或失败时保留旧预览，尚未处理项不变。换缓存路径时，新映射入库后才回收已无其他索引引用的旧自有缓存；共享、外部、自定义命名、源文件及目录链接中的音频不清理。

快速预览用 20 ms 双声道能量窗口判断响度，RMS 低于 0.001（约 -60 dBFS）或峰值低于 0.003 时有界延长采集；始终很弱的片段保真保存并标记待确认，不自动放大。最终每音不超过设定时长，默认三个音合计最多 1.5 秒；只裁边界静音，不删除片段内部停顿，末尾做 5 ms 淡出。Vital 原生按整秒采集并保留 30% 尾音，实际参数如实保存。慢起音重试可能更耗时，短文件不等同于所有插件初始化都更快。

「已生成（含待确认）」筛选包含真实存在的预览文件，不只统计已确认项。Vital 原生输出默认标记「已生成待确认」：音频已经保存，可以试听，但仍须核对预制及外部资源。生成或复用后自动展示已生成项，并清除冲突的搜索、音源和收藏筛选；启动时会显示已保存预览数量，也可点击「查看已生成」。设置中的「当前音色库数据目录」可用于核对是否打开了同一套音色库。

点击生成后，音色库上方立即显示准备状态，随后显示当前音色、处理数量、总体百分比与用时。任务结束后保留生成、复用、失败和跳过原因汇总；生成方式未选择与已配置但暂不可用分别统计，可通过设置图标打开对应配置区域。执行保留后端选择，独立传递本轮只读可用性检查，队列在有效预览复用后才判定阻断；具体原因批量写入已存在记录的最近任务结果，不因跳过新建索引项。安装目录中发现插件不等于生成环境已就绪。大批量进度合并刷新，不逐项重新筛选整个音色库或写入运行记录。

支持 `.vital`、`.vitalbank`、`.fxp`、`.SerumPreset`、`.fxb`，以及 Spire 的 `.spf` / `.spf2` / `.sbf` / `.swzip` 扫描规则。Spire 原生预制和银行目前标记「待适配」，不进入预览队列；旧 `.fxp` 仅可在核对后手动指定，不凭 Spire 目录名称猜测未知 FXP。自动识别优先采用独有后缀和已核对的 VST 文件头；最近的目录名称可辅助区分 Serum 版本。已核对的文件头优先于误放的目录名称。未知文件头、版本冲突或缺少可靠依据的共享格式保留为「待识别」，不会进入渲染队列；可在详情中核对并手动指定音源，选择会随下次扫描保留。

识别依据与标签随索引保存，收藏和反馈不会因重新分类而丢失。音源发生变化时旧预览失效，需要重新生成。明确指定音源的目录优先于重叠的自动识别目录。识别文件归属不代表实际插件可加载或已通过兼容性验证。

扫描同时保存原文件 MD5 和 SHA256。相同 MD5、音源及包内位置的副本保留各自路径、ID、收藏与反馈，只选一个代表项显示和渲染；「显示重复项」可查看所有路径，搜索支持 MD5，「导出 MD5 索引」保存完整映射。原代表文件丢失时会提升可用副本，只有 SHA256 与有效音频映射也一致才复用旧预览，复用后仍需试听确认。不同银行内部条目不因共享包文件 MD5 而合并。

插件扫描只读取 Windows PE / 版本 / 必要的 VST 导出，或 macOS Info.plist / Mach-O 元数据，不加载或执行插件。熟悉的文件名不足以识别产品；不相关 DLL、应用程序和 SerumFX 效果器不会作为已支持乐器关联。默认优先当前适配方式使用的格式，再选择较新的版本；除已实现的 Serum 2 原生状态适配外，发现 VST3 也不代表其预制格式已适配。

Vital 从独立程序改选 VST 时会清除旧的原生程序并转为未配置，需要另外指定兼容宿主；改回独立程序时恢复原生方式并清除旧 VST 关联。

Vital 包内条目在完整内嵌资源检查通过后可用原生 CLI 生成；Worker 重核原包与条目的复合哈希，只在任务私有临时目录加载，不导入全局音色资源。原有 ID、复合内容指纹和独立音色适配器标识保持兼容；未知资源类型、缺数据及超限条目显示「无法预览」。FXB 等未实现的银行仍只索引，不伪造音色槽位。Serum 2 原生 `.SerumPreset` 通过可选 DawDreamer VST3 后端转换为当前插件状态并回读核对；额外依赖固定在 `scripts/renderers/requirements-serum2.txt`，安装步骤见[可选宿主](docs/rendering.md#可选-dawdreamer-宿主)。Spire 目前没有内置原生预制渲染器，也没有真实插件验收。

「外部工作进程」接受自定义本地渲染器，采用 JSON 请求、结果映射和适配器版本标记，详见 [进程协议](docs/rendering.md)。程序不会执行 shell 命令模板。

## 数据与维护

0.7.6 中，仅 Preview 缺失时可读取 Config 的来源配置重新扫描和生成；仅 Config 缺失时从现有库设置重建目录配置，分类规则优先迁入兼容旧副本，没有外置默认文件时使用 Core 嵌入的同一份默认 JSON。已有个人规则、损坏配置和旧规则原件不被默认内容静默覆盖。旧自动定位记录指向不存在的库时，提示并新建当前程序旁 Preview；用户手动选择导入或通过 `--data-directory` 明确指定的不存在来源仍报错。新建库不会恢复未备份的收藏、标签、反馈、手工分类和个人规则，须退出程序后手动恢复对应旧 Preview / Config。清理缓存继续使用界面的「清空预览」。本次不改变缓存键、schema 2 或 4 GiB 资源政策。

旧库兼容迁移将数据库、设置、分类规则、手工元数据和引用预览复制并校验到固定 `Preview`，保留源数据库及其 schema、WAL 中的已提交记录、`Config` 与原音频作回退。应用设置及记录的未知 JSON 字段保留，缺失的已生成音频保留原映射并提示。已有库只归并自身引用的外部预览和基准；用户确认的「导入旧版音色库」先在暂存目录准备并验证所选库，成功后才完整备份当前 Preview 并发布，不合并两套库。「清空预览」仅处理当前记录或基准明确引用、可确认独占的缓存，不删除预制、收藏或标签。共享、外部和未知音频 / 基准保留并报告，不凭缓存文件名删除孤立文件；清理不代表整个目录变空。

所有预制文件均只读。索引在 Windows 使用自带的 `winsqlite3.dll`，macOS 使用系统 `libsqlite3.dylib`，旧数据库自动迁移并在下次可访问的扫描中回填 MD5；Vital 输出 PCM16，DawDreamer 桥接保留 float32 原始输出，先校验临时文件，再按设置压缩或保留 WAV 并原子提交。试听解码 WAV / M4A 后，在 Windows 通过 WinMM、macOS 通过 AudioQueue 输出内存 PCM16 音频，独立音量不修改预览文件，也不依赖 Windows Media Player。生成缓存包含音色内容、插件/程序指纹、实际版本、试听模板及适配器版本；存储编码格式不进入缓存键，默认复用依据已保存模板校验完整预览，不因当前配置变化自动重渲染。源文件内容或音源归属变化会使旧映射失效。单文件外部资源的变更跟踪仍需专用适配器补充。

不会自动下载模型或商业音源，不包含用户预制。随包的 uv 保留双重许可文件，Windows 私有 C++ 运行库保留再分发声明；Python / DawDreamer 由用户一键下载到本地 Preview，不混入程序包或 CI 产物。当前仅调用用户安装的音源；本仓库未替用户选定项目发行许可证。
