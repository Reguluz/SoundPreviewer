# SoundPreviewer

把合成器音色生成短试听片段，在一个音色库里搜索、筛选和播放，减少逐个打开音源试音的时间。已有预览可以直接试听，无需打开 DAW。

**当前版本：0.6.0 开发版**，供朋友测试；本文按 2026-10-20 的功能编写。使用中遇到问题，请保留音源版本、错误提示和复现步骤。

## 下载与安装

从 [GitHub Releases](https://github.com/Reguluz/SoundPreviewer/releases) 下载对应平台的包。如果尚无对应版本的 Release，可到 [自动构建页面](https://github.com/Reguluz/SoundPreviewer/actions/workflows/desktop.yml)，打开标记为成功的构建，在 Artifacts 下载 `packages-平台`。Actions 测试包有保留期限，下载可能需要登录 GitHub。

| 你的电脑 | 选择的包 | 打开方式 |
| --- | --- | --- |
| Windows 10 1809 及以上 / Windows 11，x64 | `win-x64-setup.exe`；免安装选 `win-x64-portable.zip` | 安装后从开始菜单打开；免安装版先完整解压，再打开 `SoundPreviewer.exe` |
| macOS 12 及以上，Apple Silicon（M 系列） | `osx-arm64.dmg` 或 `osx-arm64.zip` | 将 `SoundPreviewer.app` 复制到可写的独立文件夹后打开，如 `~/Applications/SoundPreviewer` |
| macOS 12 及以上，Intel | `osx-x64.dmg` 或 `osx-x64.zip` | 与 Apple Silicon 版相同，注意选择 x64 包 |

表中系统下限来自安装包配置，不表示每个旧系统版本都已实机验证。Mac 请勿直接在只读 DMG 中运行。安装包尚未做 Windows 代码签名和 Apple 签名、公证，系统可能提示来源未知；请核对下载来源，以及同一发布页或构建产物中的 `SHA256SUMS-平台.txt`。Linux 和 Windows ARM64 尚无专用发行包。

程序已包含所需的 .NET 运行库，普通使用无需安装开发工具。**音源插件、音色文件和授权需自行准备**；本项目不附带商业音源或私人音色。生成新预览需要本机安装相应音源，播放已有预览不需要再次加载音源。

## 目前支持哪些音源

“可生成”表示已有生成方式，具体音源版本、授权和外部资源仍须在你的电脑上核对。Windows 与 Mac 共用操作界面；安装包能启动与某个插件实际能生成声音是两项不同的检查。

| 音源 | 可生成预览的音色文件 | 生成前需要准备 | 已有真实样本验证 |
| --- | --- | --- | --- |
| **Vital** | 独立 `.vital` | Windows / Mac 的 Vital 独立程序，使用「Vital 原生」 | Windows 历史样本；Apple Silicon 上的 Vital 1.6.4 测试音色 |
| **Serum 1** | 独立 `.fxp` | VST2 插件及可选 DawDreamer 环境 | Windows Serum 1.334 x64；五个音色完成 1 / 2 / 4 条实测，见[实测说明](docs/parallel-rendering.md#060-windows-五样本实测2026-10-20)；Mac 尚待真实插件验证 |
| **Serum 2** | 原生 `.SerumPreset` | VST3 插件及带 Serum 2 依赖的 DawDreamer 环境 | Apple Silicon / Serum 2 2.0.23 的两个工厂音色；Windows、Intel Mac 尚待真实插件验证 |
| **Sylenth1** | 独立 `.fxp` | Windows x86 插件可用随包宿主；其他匹配架构的 VST2 需 DawDreamer | Windows Sylenth1 2.2.1.2 x86；五个音色完成 1 / 2 / 4 条实测，其他组合尚待验证 |
| **Spire** | 暂不生成 | 可扫描 `.spf`、`.spf2`、`.sbf`、`.swzip`，保留为待适配记录 | 尚无真实插件生成验证 |

以下文件可以被索引，但**当前不能直接生成预览**：Vital `.vitalbank` 的包内条目、`.fxb` 银行，以及其他未适配的银行内容。请先在对应音源中导出独立音色，再添加其目录。Serum 2 的旧 `.fxp` 需在 Serum 2 中导入并另存为 `.SerumPreset`，直接改扩展名无效。无法可靠判断归属的文件显示「待识别」，可在详情中核对后指定音源。

更多版本与样本记录见 [音源验证记录](docs/rendering.md#本机验证记录)。这些样本不代表所有音色、插件版本或外部采样资源都已验证。

## 第一次使用

### 1. 扫描已安装的音源

点击顶部「扫描音源」，在「音源与设置 → 已发现音源」查看结果。程序会从常见安装位置查找；找不到时，在「目录」页添加音源安装目录后重新扫描。

可选中正确的插件版本，点击「使用选中版本」。优先使用与本机架构匹配的插件。扫描到插件后，还需确认下一步的生成方式；扫描本身不会演奏音色。

### 2. 确认预览生成方式

在「音源与设置 → 预览生成」检查配置：

- **Vital**：选择 Vital 独立程序，方式为「Vital 原生」。只有 VST 插件文件时，不能直接使用这条原生路径。
- **Windows 的 Sylenth1 x86**：匹配后可使用随包的独立宿主。如果提示缺少运行库，请从 [Microsoft 官方页面](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/) 安装 VC++ **x86** 运行库。
- **Serum 1 / Serum 2 / 使用 DawDreamer 的 Sylenth1**：先完成下方的「可选生成环境」，将其返回的 Python 路径填入「渲染程序」，方式选「DawDreamer」，并关联正确的插件文件。

检查音源的实际版本，点击「保存设置」。Python、DawDreamer 和插件需要匹配架构；Windows 的 DawDreamer 路径使用 x64，不能加载 x86 插件。

0.6.0 在同一页提供「并行数量」：新安装默认「自动」，也可手动选择 **1 / 2 / 4 / 8 / 16 条**。自动按物理核心数选择档位，四核优先 4 条，再按实际内存开销限制同时运行数量。已有的串行设置和各音源多开选择会保留；同一种音源仍需勾选「允许同时生成」并保存。首次安装或更新 Vital 后先单独生成一次。更换关联插件或版本后会重置该音源的并行许可。

生成期间以**主程序和全部生成子进程合计 2 GiB** 为内存目标。音源先单条校准，接近目标时暂不启动新任务，超限会安全停止并保留已完成预览。界面显示当前内存、并行限制及原因；手动高档位也遵守同一目标。插件瞬时分配可能越过采样间隔，因此这不是操作系统级硬上限。出现不稳定时选「1 条」即可恢复串行；旧音色记录和预览继续使用。

### 3. 添加音色文件夹

在「音源与设置 → 目录」添加音色所在文件夹。混合音色包可选「自动识别（混合音色包）」，无需先按音源拆目录；也可以明确指定某一种音源。

点击顶部「扫描音色」。主表显示名称、音源、分类和状态；程序只读取原音色文件，不修改它们。

### 4. 设置试听模板

打开「音源与设置 → 试听与存储」：

- 「快速预览」默认开启，每个音区 **0.5 秒**，可设 **0.1–4 秒**。
- 默认低、中、高音分别为 **C2、C4、C6**；生成后的播放顺序为 **中 → 高 → 低**。
- 关闭快速预览后，可设置按键时长与尾音；使用 Vital 时，可点击「采用 Vital 原生参数」。

保存设置后生效。修改模板不会自动覆盖已有有效预览；需要更新某个音色时，可单独重新生成。

### 5. 生成并试听

建议先选一个音色，在详情中点击「重新生成此音色」，核对三个音区后再批量处理。点击「生成 / 继续」会处理全库可生成的音色，已有完整预览默认复用；只想处理当前搜索结果时，点击「生成筛选结果」。

生成时可查看数量、进度、内存和原因，点击「停止」会保留已完成结果；下次继续未完成项。首次生成可能先建立声音参照、校准内存，慢起音也可能延长采集，因此最终试听很短不代表生成耗时一定很短。并行档位表示同时处理音色的上限，实际数量还受内存及音源多开设置限制。

选中音色后，用底部按钮播放、停止，或直接试听「中 / 高 / 低」音区。拖动进度条定位，右侧滑块调音量。「已生成待确认」表示已有声音可听，还需要核对是否对应目标音色、外部资源是否完整。

### 6. 整理音色库

搜索可查找名称、标签、目录或 MD5；音源、状态、来源、分类、标签与收藏筛选可以组合使用。重复文件默认合并显示一个代表项，勾选「显示重复项」可查看其他路径。

选中音色后点击「编辑标签与分类」，用逗号或换行分隔并保存。保存空内容表示明确清空；重新扫描和自动分类不会覆盖手工内容。「恢复自动」重新采用最近的自动结果。收藏和喜欢 / 不喜欢反馈也会保存在本地。

## 可选生成环境：Serum 与 DawDreamer

仅使用 Vital 原生或 Windows 随包的 Sylenth1 x86 宿主时，可以跳过本节。

先准备标准 **CPython 3.11 或 3.12**。Windows 使用 x64；Mac 使用与插件相同的 Apple Silicon 或 Intel 架构。建议使用标准 CPython，避免 Conda 环境携带的旧运行库影响宿主。

Windows：在程序文件夹打开 PowerShell，运行随包脚本，替换为本机 Python 的实际路径：

```powershell
powershell -ExecutionPolicy Bypass -File .\Prepare-DawDreamer.ps1 -PythonPath "C:\Python312\python.exe" -IncludeSerum2
```

Mac：在终端中运行 app 内的准备脚本，替换 app 和 Python 的实际路径：

```bash
bash "$HOME/Applications/SoundPreviewer/SoundPreviewer.app/Contents/MacOS/Prepare-DawDreamer.sh" \
  --python /实际路径/python3.12 --include-serum2
```

不使用 Serum 2 时，可以去掉 `-IncludeSerum2` / `--include-serum2`。脚本会联网下载固定依赖，在 `Preview/renderers` 建立独立环境，并显示 `EnvironmentPythonPath`；把这个路径填入对应音源的「渲染程序」。它只检查空宿主是否可运行，不替你安装商业插件或完成音色验证。准备好后，日常扫描与生成使用本地文件。

如果更改过数据目录，运行脚本时还应通过 `-DataDirectory`（Windows）或 `--data-directory`（Mac）指定当前数据目录。完整参数及故障诊断见 [生成环境说明](docs/rendering.md#可选-dawdreamer-宿主)。

## 数据保存、清理与升级

新安装默认将音色索引、预览、设置、收藏、标签和分类保存在程序旁的 **Preview**，Portable 版相同。Windows 位于 `SoundPreviewer.exe` 同目录；Mac 位于 `.app` 旁边。请使用有写入权限的文件夹。

| 你要做什么 | 操作与结果 |
| --- | --- |
| 查看实际数据位置 | 「音源与设置 → 试听与存储」查看当前数据库与音频目录 |
| 释放试听缓存空间 | 点击「清空预览」；保留音色记录、收藏、反馈、标签和分类，之后可重新生成 |
| 换盘或更换数据位置 | 点击「更改目录」，选择新的空目录，再选「迁移旧预览」或「清除旧预览」；记录与个人内容都会复制 |
| 打开旧版本记录 | 点击「打开已有音色库」，选择含 `library.db` 的原目录；这一步只关联位置，不搬文件 |
| 备份 | 退出应用后复制整个数据目录，保留原音色与外部资源 |

清理只处理本库可确认归属的预览及声音参照。共享、外部或归属不明的文件会保留并提示，所以「清空预览」不代表把整个目录删空。目录迁移后，旧数据库与分类规则会保留为回退备份；核对新库和试听正常后，再处理原目录。

升级时先退出程序。Windows 安装版在原目录运行新安装包；Portable 在原目录替换程序文件；Mac 替换 `.app`。**保留 Preview 和库定位文件 `library-location.json`**，新版本会继续读取旧记录和有效缓存。降回旧程序时应使用升级前备份。

Portable 表示免安装。直接剪切整个程序文件夹不会自动改写库内的音频、音色来源或插件绝对路径；换位置请先使用应用内迁移，再移动程序并打开目标库。程序不提供应用内自动更新，后续版本从 GitHub 下载。

## 常见问题

| 情况 | 处理方法 |
| --- | --- |
| 扫描到音源，但提示未配置 | 到「预览生成」检查生成方式、渲染程序和关联插件；然后保存设置 |
| 音色显示「待识别」 | 在详情中核对并指定所属音源，再生成；不要按相似文件名猜测归属 |
| 银行或 Spire 显示「待适配」 | 当前只保留索引，尚不能直接生成这类文件 |
| 生成声音与目标不符 | 暂不确认，检查插件版本、授权、采样与波表路径；记录该音色和错误原因 |
| 不明白「加载防错检查」 | 它记录音源刚启动时的默认声音，避免加载失败后把默认声保存为目标音色；支持的生成方式会自动准备参照，通常无需手动操作 |
| 更新后看不到原记录 | 先核对数据目录，再用「打开已有音色库」关联旧库；不要先删除原目录 |
| 想用新模板重做试听 | 单独重新生成所选音色；「全量重渲染（覆盖）」会处理全库，不受当前搜索筛选限制 |

反馈问题可提交到 [GitHub Issues](https://github.com/Reguluz/SoundPreviewer/issues)，附上程序版本、系统与架构、音源版本、所用文件格式和「运行记录」中的相关错误。无需上传商业插件、授权文件或完整私人音色库。
