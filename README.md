# SoundPreviewer

把合成器音色生成短试听片段，在一个音色库里搜索、筛选和播放，减少逐个打开音源试音的时间。已有预览可以直接试听，无需打开 DAW。

**当前版本：0.9.0 开发版**，供朋友测试；本文按 2026-10-21 的功能编写。使用中遇到问题，请保留音源版本、错误提示和复现步骤。

## 下载与安装

从 [GitHub Releases](https://github.com/Reguluz/SoundPreviewer/releases) 下载对应平台的包。如果尚无对应版本的 Release，可到 [自动构建页面](https://github.com/Reguluz/SoundPreviewer/actions/workflows/desktop.yml)，打开标记为成功的构建，在 Artifacts 下载 `packages-平台`。Actions 测试包有保留期限，下载可能需要登录 GitHub。

| 你的电脑 | 选择的包 | 打开方式 |
| --- | --- | --- |
| Windows 10 1809 及以上 / Windows 11，x64 | `win-x64-setup.exe`；免安装选 `win-x64-portable.zip` | 安装后从开始菜单打开；免安装版先完整解压，再打开 `SoundPreviewer.exe` |
| macOS 12 及以上，Apple Silicon（M 系列） | `osx-arm64.dmg` 或 `osx-arm64.zip` | 将 `SoundPreviewer.app` 复制到可写的独立文件夹后打开，如 `~/Applications/SoundPreviewer` |
| macOS 12 及以上，Intel | `osx-x64.dmg` 或 `osx-x64.zip` | 与 Apple Silicon 版相同，注意选择 x64 包 |

表中系统下限来自安装包配置，不表示每个旧系统版本都已实机验证。Mac 请勿直接在只读 DMG 中运行。安装包尚未做 Windows 代码签名和 Apple 签名、公证，系统可能提示来源未知；请核对下载来源，以及同一发布页或构建产物中的 `SHA256SUMS-平台.txt`。Linux 和 Windows ARM64 尚无专用发行包。

程序已包含所需的 .NET 运行库，普通使用无需安装开发工具。**音源插件、音色文件和授权需自行准备**；本项目不附带商业音源或私人音色。生成新预览需要本机安装相应音源，播放已有预览不需要再次加载音源。

**首次完整解压后即可打开，无需先复制旧 Preview 或 Config。** 缺失的必要内容会自动建立，再按下方步骤添加音色目录、扫描并生成。要继续使用原有收藏、标签、手工分类和预览，请保留或手动恢复旧目录；新建空库不会自动找回这些个人数据。

## 目前支持哪些音源

“可生成”表示已有生成方式，具体音源版本、授权和外部资源仍须在你的电脑上核对。Windows 与 Mac 共用操作界面；安装包能启动与某个插件实际能生成声音是两项不同的检查。

| 音源 | 可生成预览的音色文件 | 生成前需要准备 | 已有真实样本验证 |
| --- | --- | --- | --- |
| **Vital** | 独立 `.vital` | Windows / Mac 的 Vital 独立程序，使用「Vital 原生」 | Windows 历史样本；Apple Silicon 上的 Vital 1.6.4 测试音色 |
| **Serum 1** | 独立 `.fxp` | VST2 插件及一键准备的 DawDreamer 环境 | Windows Serum 1.334 x64；历史五音色并行实测见[并行说明](docs/parallel-rendering.md#060-windows-五样本实测2026-10-20)；Mac 尚待真实插件验证 |
| **Serum 2** | 原生 `.SerumPreset` | VST3 插件及带 Serum 2 依赖的 DawDreamer 环境 | Apple Silicon / Serum 2 2.0.23 的两个工厂音色；Windows、Intel Mac 尚待真实插件验证 |
| **Sylenth1** | 独立 `.fxp` | Windows x86 插件可用随包宿主；其他匹配架构的 VST2 需 DawDreamer | Windows Sylenth1 2.2.1.2 x86；五个音色完成 1 / 2 / 4 条实测，其他组合尚待验证 |
| **Spire** | 暂不生成 | 可扫描 `.spf`、`.spf2`、`.sbf`、`.swzip`，保留为待适配记录 | 尚无真实插件生成验证 |

以下文件可以被索引，但**当前不能直接生成预览**：Vital `.vitalbank` 的包内条目、`.fxb` 银行，以及其他未适配的银行内容。请先在对应音源中导出独立音色，再添加其目录。Serum 2 的旧 `.fxp` 需在 Serum 2 中导入并另存为 `.SerumPreset`，直接改扩展名无效。无法可靠判断归属的文件显示「待识别」，可在详情中核对后指定音源。

更多版本与样本记录见 [音源验证记录](docs/rendering.md#本机验证记录)。这些样本不代表所有音色、插件版本或外部采样资源都已验证。

## 第一次使用

### 1. 扫描已安装的音源

点击顶部「扫描音源」，在「音源与设置 → 已发现音源」查看结果。程序会从常见安装位置查找；找不到时，在「目录」页添加音源安装目录后重新扫描。

可选中正确的插件版本，点击「使用选中版本」。优先使用与本机架构匹配的插件。扫描到插件后，还需确认下一步的生成方式；扫描本身不会演奏音色。

### 2. 确认预览生成方式

在「音源与设置 → 预览生成」检查配置：

- **Vital**：选择 Vital 独立程序，方式为「Vital 原生」。只有 VST 插件文件时，不能直接使用这条原生路径。
- **Windows 的 Sylenth1 x86**：匹配后可使用随包的独立宿主。如果提示缺少运行库，请从 [Microsoft 官方页面](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/) 安装 VC++ **x86** 运行库。
- **Serum 1 / Serum 2 / 使用 DawDreamer 的 Sylenth1**：点击本页「一键准备生成环境」，首次联网下载，成功后自动填入私有环境路径；再核对关联的插件文件。

检查音源的实际版本，点击「保存设置」。私有环境与当前程序架构一致；Windows 的 DawDreamer 路径使用 x64，不能加载 x86 插件。

「渲染程序」与「已关联插件」是两个位置：Serum 1 的 DawDreamer 方式应选择 Python 程序，插件则选择 64 位 `Serum_x64.dll`，不能把 DLL 当作 Python。未配好的音源也能先保存，不会挡住其他设置；「配置状态」会分别说明缺少什么。若已在本程序的 `Preview/renderers` 准备默认环境，空白的 DawDreamer 程序路径会自动填入；自选和暂时离线的路径会保留。

**Sushi（本地研究）**：保留手动配置入口，安装包不包含该宿主，也不自动切换。已有实验的适用范围及构建入口见[研究记录](docs/headless-host-research.md)。日常公开测试采用上面的私有 DawDreamer 环境。

「加载防错检查」通常自动进行。内置 Windows x86 Sylenth1 宿主遇到启动声音随机波动时，可改用逐音色的精确状态回读；状态与目标不一致或无法核验时仍拒绝保存。这不表示声音比对已稳定，生成结果仍需试听确认。Vital 原生方式不支持这项声音参照检查，也不会因此被禁止生成。

0.7.4 修正 Sylenth1 将已验证的旧预设版本标记改写后被误判的情况，其余音色状态仍须完全一致。若提示“状态完全未变”或回读格式不同，当前插件未能提供可核验的加载结果；请使用匹配版本的 Sylenth1，或在对应版本中重新导出独立 FXP。这类明确不兼容的加载不会在同一次队列中重复尝试。

同一页提供「并行数量」：新安装默认「自动」，也可手动选择 **1 / 2 / 4 / 8 / 16 条**。自动按物理核心数选择档位，四核优先 4 条，再按实际内存开销限制同时运行数量。各音源默认开启「允许同时生成」；已明确关闭的设置继续保留，更新或重新关联音源不会重置选择。首次安装或更新 Vital 后先单独生成一次。

从 0.7.5 起，按 16 GB 及以上内存的电脑使用需求，生成期间以**主程序和全部生成子进程合计 4 GiB（4096 MiB）RSS** 为内存目标。实际占用达到 **3.75 GiB（3840 MiB）** 时暂停启动新任务，超过 4 GiB 会停止本批并保留已完成预览。音源先单条校准，启动判断仍同时计算实际占用和预测预留，因此可能提前限流，不保证占满 4 GiB 或始终达到 8 条并行。界面区分实际占用、预留和并行限制；插件瞬时分配可能越过采样间隔，因此这不是操作系统级硬配额。出现不稳定时选「1 条」即可恢复串行；旧音色记录、缓存格式和数据库 schema 不变。

### 3. 添加音色文件夹

在「音源与设置 → 目录」添加音色所在文件夹。混合音色包可选「自动识别（混合音色包）」，无需先按音源拆目录；也可以明确指定某一种音源。

点击顶部「扫描音色」。主表显示名称、音源、分类和状态；程序只读取原音色文件，不修改它们。

音色库的「来源」下拉框显示每个路径的音色总数、去重数量、目录内重复副本和跨来源相同音色的数量。跨来源统计也包含主记录所在目录。这里统计扫描索引总量，搜索不会改变它。全部来源默认每组显示一项；选择单独来源时保留该目录自己的代表项，生成时映射到同一个主记录，继续共享缓存。

音色来源与音源安装目录显式保存在程序旁的 **`Config/directories.json`**（Windows 与 Portable 为 EXE 旁的 Config，Mac 为 `.app` 旁的 Config）。音色库定位记录和个人分类规则也集中到 Config。旧根目录 JSON 和 Preview 中的规则会兼容迁入，保留原件，已有 Config 优先。首次使用从原有设置导出，以后启动以该文件为准；「目录」页的修改会同步保存。可点击「目录 JSON」打开，退出程序后编辑并重启。保留 `FormatVersion` 和已有来源的 `Id`，可修改 `Path`、`Synth`、`AutoDetect`、`Enabled` 及 `PluginDirectories`；音源名称使用 `Vital`、`Serum1`、`Serum2`、`Sylenth1` 或 `Spire`。JSON 支持注释、尾逗号，相对路径按程序所在目录解析。文件损坏会明确提示，不覆盖原件；运行中手改文件后应先重启，再在界面保存。

### 4. 设置试听模板

打开「音源与设置 → 试听与存储」：

- 「快速预览」默认开启，每个音区 **0.5 秒**，可设 **0.1–4 秒**。
- 默认低、中、高音分别为 **C2、C4、C6**；生成后的播放顺序为 **中 → 高 → 低**。
- 关闭快速预览后，可设置按键时长与尾音；使用 Vital 时，可点击「采用 Vital 原生参数」。

保存设置后生效。修改模板不会自动覆盖已有有效预览；需要更新某个音色时，可单独重新生成。

### 5. 生成并试听

建议先选一个音色，在详情中点击「重新生成此音色」，核对三个音区后再批量处理。点击「生成 / 继续」会处理全库可生成的音色，已有完整预览默认复用；只想处理当前搜索结果时，点击「生成筛选结果」。

生成时实时显示已处理、成功（分别列出新生成与复用）、失败，以及未配置、达到重试限制的数量。点击「停止」会保留已完成结果；下次继续未完成项。首次生成可能先建立声音参照、校准内存，慢起音也可能延长采集，因此最终试听很短不代表生成耗时一定很短。

音色库总量与本次处理队列分别显示。例如所选 14007 条、重复 1456 条，去重后为 12551 个；其中待识别 5130 个、当前不支持生成的格式或银行条目 989 个，进入处理队列的就是 6432 个。队列也包括复用已有预览和提示未配置的项目，分母不是整个库的去重总量。进度区固定预留空间，说明换行和内存提示显隐不会推动下方列表。

「运行 1/1」的分母为当前实际可用并行上限；下方另列设定上限和内存允许数量。例如设为 8、内存允许 3，但该音源被手动关闭「允许同时生成」，当前上限仍为 1。界面会显示限制原因；首次测量、准备声音参照和队列末尾剩余数量也会影响当前上限。默认允许同一种音源并行，仍受 4 GiB 内存目标与预测预留限制。

0.7.0 优先连续处理同一种音源，音源组按本次选择中首次出现的顺序排列，组内保留原顺序。同源允许并行时先集中生成；不允许同源多开时，可以用其他音源补充空闲位置。该版本当时采用 2 GiB 目标，0.7.5 起采用上文的 4 GiB 目标。每个音色仍独立加载插件，同源排序的提速尚未单独测量。

选中音色后，**按空格键可从头播放当前音色预览**，播放中再次按下也会从头重播。按住空格不会连续重启；搜索、标签等文本输入及筛选控件保留原有空格操作。底部播放区常驻显示快捷键提示，也可用按钮播放、停止，或直接试听「中 / 高 / 低」音区。拖动进度条定位，右侧滑块调音量。「已生成待确认」表示已有声音可听，还需要核对是否对应目标音色、外部资源是否完整。

### 6. 整理音色库

搜索可查找名称、标签、目录或 MD5；音源、状态、来源、分类、标签与收藏筛选可以组合使用。重复文件默认合并显示一个代表项，勾选「显示重复项」可查看其他路径。

选中音色后点击「编辑标签与分类」，用逗号或换行分隔并保存。保存空内容表示明确清空；重新扫描和自动分类不会覆盖手工内容。「恢复自动」重新采用最近的自动结果。收藏和喜欢 / 不喜欢反馈也会保存在本地。

### 7. 将音色带到 DAW

优先适配目标是 Windows FL Studio 的“拖到空白处创建音源并加载音色”，后续再扩展 Windows / Mac 的 FL Studio、Bitwig 和 Live。当前先提供文件定位：选中音色，点击「定位音色文件」，在资源管理器或访达中选中原文件。包内条目和银行会显示「定位音色库文件」，定位到所属的银行或包文件；在对应音源中打开后选择需要的条目。

在 FL Studio 中可先添加对应音源，再通过音源或 Wrapper 的加载菜单打开定位到的文件。原生音色尚未自动转换成 FL 的 `.fst` 通道预设，因此此版本不提供空白轨道自动创建功能。具体区别见[DAW 音色传递](docs/daw-transfer.md)。

选中独立音色后，按住详情里的「拖出音色」向外拖动。传递的是原音色文件，仅允许复制，来源和预览保持原位。请先在 DAW 打开对应音源，再拖到它支持音色文件加载的位置；能否接收取决于音源、DAW 的版本及落点。

当前支持拖出独立 `.vital`、Serum 1 / Sylenth1 `.fxp`、Serum 2 `.SerumPreset`、Spire `.spf` / `.spf2`。音色包、银行、包内条目、未识别或缺失来源不提供此操作。此入口尚未经过真实 DAW 的端到端验收，原生格式可拖出不表示接收方一定加载成功；拖到空白轨道后自动创建音源仍需针对具体 DAW 适配。已核对的接收方式和版本边界见[DAW 音色传递](docs/daw-transfer.md)。

## 可选生成环境：Serum 与 DawDreamer

仅使用 Vital 原生或 Windows 随包的 Sylenth1 x86 宿主时，可以跳过本节。

打开「音源与设置 → 预览生成」，点击 **「一键准备生成环境」**。无需了解 Python，也无需单独安装 Python 或 uv。首次需要联网，完成后可离线生成；Serum 2 所需组件也会一并准备。下载或检查失败时保留已有环境和缓存，可稍后重试。

程序只随包携带下载工具 uv；Python、DawDreamer 和下载缓存保存在程序旁的 **`Preview/renderers`**。不修改系统 PATH、Python 注册信息或用户的 uv / Python 配置。Windows 所需的 x64 C++ 运行库使用私有副本，无需为这条生成路径另装运行库。

成功后会自动补齐未配置且已发现匹配插件的音源，并修复本程序私有环境的失效旧路径；已有自选生成方式和可用的旧 Python 环境保留。未扫描到插件时，请先扫描音源，再选择版本。准备过程只检查空宿主，不安装商业插件，也不代表所有音色已通过验证。

关闭程序后，可把整个程序目录连同 **Preview 与 Config** 一起移动；新私有环境使用相对清单，重开时自动定位。原音色文件、插件以及以前手动配置的外部环境仍需核对实际路径。命令行与高级参数见 [生成环境说明](docs/rendering.md#可选-dawdreamer-宿主)。

## 数据保存、清理与升级

音色索引、生成的预览 WAV、设置、收藏、标签和分类固定保存在程序旁的 **Preview**，安装版与 Portable 版相同。Windows 位于 `SoundPreviewer.exe` 同目录；Mac 位于 `.app` 旁边，不写入 app 内部。程序目录不可写时会明确报错，请将程序放到可写的独立文件夹。

0.7.6 支持目录缺失后重新建立必要配置：

| 启动时的目录情况 | 程序行为 |
| --- | --- |
| Preview 和 Config 都没有 | 无可迁入旧库时新建空库与默认配置，可重新添加目录、扫描和生成 |
| 只有 Preview 缺失 | 保留并读取 Config 中的来源配置，可重新扫描、生成预览 |
| 只有 Config 缺失 | 继续读取 Preview 的记录和预览，从现有库设置重建目录配置；分类规则优先读取兼容旧副本，没有时建立默认规则 |
| Preview 和 Config 都存在 | 继续使用已有记录、配置与有效缓存，不以默认内容覆盖个人文件 |

若自动定位到的旧库已不存在，会提示并在当前程序旁新建 Preview；手动指定的旧库导入来源不存在时仍会报错。缺失恢复只重建必要默认内容，不会覆盖损坏的已有配置。音色可重新扫描、预览音频可重新生成；未从备份恢复的收藏、标签、反馈和手工分类不会凭空重建。需要这些记录时，请先退出程序并备份当前目录，再手动恢复旧 Preview；个人分类规则需保留或恢复对应 Config 或旧规则副本。

0.7.0 及更早版本可能沿用旧用户库和外部音频目录。0.7.1 首次启动时将这些位置作为迁移来源：先复制数据库、个人记录、分类规则和引用的预览，并校验复制结果，再在程序旁使用。旧数据库与旧音频保留作为回退备份。已有 `Preview` 会继续使用自己的记录，只将它引用的外部预览和加载防错参照复制归入，不会被另一套旧库覆盖。兼容旧记录不再意味着继续向旧目录生成音频。

| 你要做什么 | 操作与结果 |
| --- | --- |
| 查看实际数据位置 | 「音源与设置 → 试听与存储」查看当前数据库与音频目录，点击「打开 Preview 文件夹」直接打开 |
| 释放试听缓存空间 | 点击「清空预览」；保留音色记录、收藏、反馈、标签和分类，之后可重新生成 |
| 导入另一套旧版本记录 | 点击「导入旧版音色库」，选择含 `library.db` 的原目录并确认；先复制校验所选库，再备份当前完整 `Preview` 并切换，两套记录不合并 |
| 选择保存位置 | 数据固定保存在当前程序旁的 `Preview`；不再提供任意外部音频输出目录 |
| 备份 | 退出应用后完整复制 Preview 与 Config，保留原音色与外部资源 |

清理只处理本库可确认归属的预览及声音参照。共享、外部或归属不明的文件会保留并提示，所以「清空预览」不代表把整个目录删空。旧库迁入后，先核对新库记录与试听正常，再自行处理原目录。

手动导入先在临时目录复制所选库与引用音频，校验记录和设置可读后，再将当前 `Preview` 在程序旁原子改名为 `Preview-before-import-*`（末尾为唯一标识），完整保留这套记录与文件，然后切换到准备好的新库。切换失败且 `Preview` 空缺时会尽量恢复原名，并显示备份位置；不要删除提示中的备份目录。

这类备份中的记录仍含原 `Preview` 的绝对路径，不能直接作为异名旧库导入。要恢复时先退出程序并备份当前 `Preview`，再把需要恢复的备份目录还原名为 `Preview`，避免覆盖任何现有数据。旧库中缺失的已生成音频仍保留原映射并提示，迁入不会擅自清空记录。

升级时先退出程序。推荐在原程序目录直接升级：Windows 安装版运行新安装包；Portable 替换程序文件；Mac 替换 `.app`。**保留 Preview 和 Config** 可继续读取个人记录、目录配置和有效缓存；这是保留个人数据的建议，不是程序启动的前置条件。安装包不携带个人目录配置，升级或卸载会保留现有文件。导入另一套旧库时，已有 `Config/directories.json` 继续作为本程序的目录配置。旧版根目录的 JSON 也请保留，供兼容迁移和回退使用。降回旧程序时应使用升级前备份。

Portable 表示免安装。移动程序前先退出并备份，连同 `Preview` 和 `Config` 一起保留；0.9.0 一键准备的私有环境随目录移动，原音色、插件和手选外部 Python 环境的绝对路径仍需核对。程序不提供应用内自动更新，后续版本从 GitHub 下载。

0.7.4 分发包将托管依赖合入程序，减少根目录文件。覆盖旧 Portable 目录会保留旧依赖文件；希望使用整洁的新布局时，可退出旧程序，将新包解压到新目录。需要沿用原记录时，再完整复制旧 `Preview`、`Config` 及尚未迁移的根目录 JSON；不复制也能以新库启动。保留旧目录作为回退，恢复后核对原记录、试听和插件路径。

## 常见问题

| 情况 | 处理方法 |
| --- | --- |
| 扫描到音源，但提示未配置 | 到「预览生成」检查生成方式、渲染程序和关联插件；然后保存设置 |
| 音色显示「待识别」 | 在详情中核对并指定所属音源，再生成；不要按相似文件名猜测归属 |
| 银行或 Spire 显示「待适配」 | 当前只保留索引，尚不能直接生成这类文件 |
| 生成声音与目标不符 | 暂不确认，检查插件版本、授权、采样与波表路径；记录该音色和错误原因 |
| 不明白「加载防错检查」 | 它记录音源刚启动时的默认声音，避免加载失败后把默认声保存为目标音色；支持的生成方式会自动准备参照，通常无需手动操作 |
| 更新后看不到原记录 | 核对程序旁 `Preview` 与旧库迁移提示，保留旧数据库和原音频；不要先删除或覆盖任一目录 |
| 想用新模板重做试听 | 单独重新生成所选音色；「全量重渲染（覆盖）」会处理全库，不受当前搜索筛选限制 |

反馈问题可提交到 [GitHub Issues](https://github.com/Reguluz/SoundPreviewer/issues)，附上程序版本、系统与架构、音源版本、所用文件格式和「运行记录」中的相关错误。无需上传商业插件、授权文件或完整私人音色库。
